# 第一周 Agent 协作与 Java 工具验证课程指导方案

**本周主题：认识 Agent 的能力与局限，完成第一次人机协作和 Java 工具修复**

> 教师执行稿 v0.1｜编制日期：2026年10月16日。面向10名学生。按当前日期暂定首次课程为2026年10月18日周日8:20线上腾讯会议；周二、周三和第四次汇报的具体时刻待教师确认。若实际开课周调整，日期整体顺延，课程顺序和验收标准保持不变。

## 一、任务目标

1. 通过一次完整的 Agent 协作演示，理解 Agent 不只是对话工具，还能根据任务生成内容、修改文件和调用工具；同时认识“表达流畅”不等于“事实正确”。

2. 能区分两类 Agent：CodeArts 是帮助我们分析、修改和运行项目的“开发助手”；Agent Lab Lite 中的仓库 Agent 是我们正在研究和完善的“业务助手”。

3. 能从 Agent 生成的 103 仓库数字导览中找出至少一处虚构信息、数据冲突或缺少证据的内容，并说明为什么不能直接采纳。

4. 能读懂一条最小调用链：用户提出问题 → Agent 选择工具 → 工具接收参数 → Java 方法执行 → 工具返回结果 → Agent 组织回答。

5. 在教师提供的 Agent Lab Lite 骨架中运行 FakeAgent，完成或解释一个 Java 搜索工具的局部修复，并通过输入场景验证修改前后的差异。

6. 使用 CodeArts 查看文件、运行项目、观察终端和代码差异；第一周允许 Agent 解释概念、分析错误和审查局部改动，不让 Agent 一次完成整个任务。

7. 完成一次结构化周汇报：说明本周任务、Agent 的一项局限、本人的一项贡献、验证证据和下周计划。第四次活动只做展示、提问和评价，不增加新教学内容。

8. 建立最初的安全边界：第一周统一使用 FakeAgent，不要求配置真实云 API；API Key 不写入代码、仓库、截图或聊天记录。

**本周完成标准：**每名学生能够运行 Agent Lab Lite；独立指出一处 Agent 输出问题；说明一个工具调用过程；完成一项个人代码、验证或内容修订；在总结汇报中用自己的话解释修改依据。

## 三、实训原理

1. **Agent协作不是把任务全部交出去。** 人负责说明目标、受众、限制和验收条件；Agent负责提出计划、生成草稿和调用工具；Java程序负责执行真实查询；最后由人检查证据并决定是否采纳。

2. **模型回答和事实数据不是一回事。** Agent能够生成通顺的文字，但在没有数据时可能猜测开放时间、库存数量或物品位置。关键事实必须来自工具、资料或人工确认。

3. **Agent的能力受工具限制。** 如果没有`search_inventory`，Agent无法可靠查询仓库；如果Java工具只返回第一条数据，Agent可能把不完整结果组织成一段很自信的回答。

4. **FakeAgent是测试替身，不是假装真实模型。** FakeAgent按照教师准备的场景返回固定计划和调用，便于所有学生看到同一个问题、重复测试和比较修复效果。界面必须明确标记FAKE，不能把模拟结果描述成真实云模型结果。

5. **第一周调用链：**

```text
学生问题
  ↓
FakeAgent选择 search_inventory
  ↓
参数 keyword=螺丝刀
  ↓
Java searchInventory 方法
  ↓
返回匹配物品列表
  ↓
Agent生成回答
```

6. **第一周最小Java知识：**只在修复需要时使用字符串、`if`、循环、`List`和方法返回值。教师不要求学生先背完整定义，也不在本周展开HTTP、JSON、数据库、Spring Boot和真实API。

7. **开发助手与业务助手：**

| 名称 | 作用 | 本周边界 |
| --- | --- | --- |
| CodeArts开发助手 | 分析项目、解释报错、查看修改、运行命令 | 先解释和给提示；一次只处理一个局部任务 |
| Agent Lab仓库助手 | 接收仓库问题、选择业务工具、组织回答 | 第一周由FakeAgent驱动，只读不写 |
| Java仓库工具 | 执行搜索、低库存查询和事实验证 | 学生需要读懂、修复和测试 |
| 人类学生 | 定义要求、核验事实、决定是否接受 | 不得把Agent首稿直接当作最终结果 |

**建议时长：60分钟；具体时间和地点待确认。**这是本周主要编码与面对面排障环节。

| 时间 | 环节 | 具体任务 |

## 八、思考题

1. 为什么Agent生成的内容很流畅，仍然不能直接认为它正确？

2. 当仓库导览中的数字错误时，问题可能来自需求、模型、Java工具和原始数据中的哪些位置？怎样逐层排查？

3. CodeArts开发助手与Agent Lab中的仓库助手有什么区别？如果把两个角色混在一起，会产生什么误解？

4. FakeAgent不是实际云模型，为什么第一周反而优先使用它？它能帮助我们验证什么，又不能证明什么？

5. 如果`search_inventory`只返回第一条匹配结果，Agent最终回答可能出现什么问题？应该怎样设计验证场景发现它？

6. 为什么修改或删除库存属于高风险操作？除了让Agent“说一声”，Java程序还应做哪些限制？

7. 当CodeArts建议一次修改很多文件时，为什么不应直接全部接受？怎样把任务缩小到一个可以解释和验证的改动？

8. 本周汇报为什么必须包括“问题、修改和验证”，而不能只展示最终页面？

9. 如果下一周要为仓库Agent增加一个新能力，你选择搜索优化、低库存查询、位置查询还是事实核验？为什么？第四周接入真实云API后，本周建立的哪些验证规则仍然必须保留？
