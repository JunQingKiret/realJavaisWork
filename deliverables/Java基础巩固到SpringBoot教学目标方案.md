# 任务目标：Java基础巩固与Spring Boot项目拓展实验

**学习主线：Java 8基础巩固 → Java 21常用特性认识 → 校园二手交易平台迭代 → Spring Boot分层开发**

> 教师共备讨论稿 v0.3｜编制日期：2026年10月12日。面向3–4名学生；教师判断其目前主要掌握基础语法，尚不能独立整合类、集合和输入。建议周期16周，每人每周约5.5–6小时课外总投入；总周期、指导时长、实际日期和具体软件版本均待教师确认。本稿不代表学生已完成相关学习。

## 一、任务目标

1. 巩固变量、字符串、分支、循环、方法和输入处理，能够独立完成重复操作的控制台菜单，理解程序执行顺序，处理常见空输入和非法选项。
2. 掌握普通类、对象、构造器、封装、集合和泛型的基本用法，能够独立编写含商品对象、集合保存和输入处理的小程序，而非只会模仿单一语法示例。
3. 理解异常处理、接口和职责拆分，在项目中区分入口、业务与存储职责，能通过手工创建对象和构造器传入依赖，为理解Spring依赖注入建立基础。
4. 在保留学校Java 8作业环境的前提下，用JDK 21开展拓展练习；认识var、文本块、switch表达式、Record等Java 8之后的常用特性，区分它们与Java 21正式新增特性，不使用预览功能作为主项目依赖。
5. 掌握Maven与Git的基础使用，能够运行统一工程、保存有意义的代码迭代、阅读差异、参与同伴审查，并写出他人可以照着运行的说明。
6. 掌握SQL/JDBC、资源关闭、参数绑定和基础事务，完成商品持久化；理解HTTP/JSON请求与响应，并能说明一条API请求如何调用业务与存储逻辑。反射、注解以短例理解为主，不要求手写完整MVC框架。
7. 理解Spring Boot、IoC/DI、Spring MVC和MyBatis的基本职责，完成本地教学API；能解释Controller → Service → Mapper/Repository → 数据库的调用路径，并验证参数校验、错误响应和事务回滚。
8. 分阶段使用AI辅助概念理解、排错和小范围改动，能区分教师提供、自己完成和AI辅助的部分；通过审查、测试与个人现场修改证明理解，不以AI生成代码替代基础学习。

**结业作品与范围：**本地运行的校园二手商品教学API，包含发布、列表、名称搜索、详情、编辑、下架和受控成交记录。使用虚构商品与昵称，不含真实支付、完整鉴权、图片上传、复杂前端或公网生产部署。若周期固定为12周，采用第四部分的降载方案，仅要求基础发布、列表、搜索API，不承诺全面掌握Spring。

## 三、实训原理

### 1. 先建立基础能力，再逐步项目化

学生从“认识语法”过渡到“独立组织程序”：读取输入 → 判断和循环 → 方法拆分 → 商品对象 → 集合保存 → 业务规则 → 持久化 → HTTP入口 → 框架装配。

每次指导只引入完成当前任务所需的1–2个知识点，采用“观察需求或错误 → 最小讲解 → 共同示例 → 独立变式 → 运行验证”的流程。不是先把所有理论讲完，也不把JDK升级等同于能力提升。

### 2. 核心名词速查

| 名词 | 通俗解释及本课用途 |
|---|---|
| JDK / JVM | JDK提供开发与运行所需工具；JVM负责执行Java程序。学生先会确认自己的项目用哪套环境 |
| 方法 | 给一段有明确职责的处理逻辑命名；通过参数接收信息，必要时通过返回值给出结果 |
| 类与对象 | 类描述一类事物的数据和行为；对象是具体实例。本课用不同Product对象表示不同商品 |
| 封装 | 把内部数据与操作放在合适的边界，控制访问；不是机械地给每个字段加读写方法 |
| 集合与泛型 | 集合管理多个对象；泛型表达集合中预期的元素类型，例如商品列表 |
| 接口 | 约定可以做哪些操作；内存存储与数据库存储可以实现同一约定，减少业务层随存储变化 |
| 异常 | 表示当前处理不能正常完成的情况；在合适边界给用户提示或向上交代，不把全部错误悄悄吞掉 |
| Maven / Git | Maven组织构建和依赖；Git记录和比较版本。两者职责不同，工具操作不能替代程序理解 |
| SQL / JDBC | SQL用于表达数据库操作；JDBC让Java调用数据库。本课先看到数据如何保存和查询 |
| HTTP / JSON | HTTP表达请求与响应；JSON是常见的数据表示格式。JSON不是网络协议，也不是数据库 |
| 反射与注解 | 注解提供元数据；反射可在运行时读取相关信息并调用方法。这里只用短例说明，不构建完整框架 |
| IoC / DI | 从全部由自己创建、连接对象，转向由容器管理；DI是把需要的依赖提供给对象的一种具体方式 |
| Spring Boot / Spring MVC | Boot帮助组织和配置应用；MVC负责Web请求处理。本课通过迁移比较职责，不只记注解名字 |
| MyBatis | 帮助把Java调用与SQL、结果映射连接起来；学生仍需理解SQL、参数、数据库约束和事务 |

名词学习方式：每人用项目中的一个例子解释1–2个术语；其他成员指出哪里不清楚。不能只背定义，必须能找到代码或请求中的对应位置。

### 3. 保留版本演进，但不按旧时间表硬赶

| 版本 | 形态/范围 | 解决的主要问题 |
|---|---|---|
| V0 | 菜单、名称数组、控制台输入等逐步形成的最小程序 | 从会语法到能独立组织输入和操作 |
| V1 | 商品普通类与职责重构 | 不再把所有字段和业务挤在入口中 |
| V2 | 商品集合、存储接口、异常边界 | 管理多个对象，表达规则，准备替换存储 |
| V3 | Maven、测试、SQL/JDBC与事务 | 工程可复现，重启保留数据，避免半成功结果 |
| V4 | HTTP/JSON API | 用请求和响应访问原有业务，不重写业务规则 |
| V5 | 反射注解短演示/选做实验 | 理解路由元数据与方法调用；不是完整MVC作业 |
| V6 | Spring Boot分层API、MyBatis与验证 | 把重复基础设施交给框架，仍能解释和维护业务 |

### 4. Java 8到Java 21的特性穿插

| 内容 | 正式版本/性质 | 教学时机与边界 |
|---|---|---|
| Lambda、Stream | Java 8已具备 | 集合基本任务通过后按需复习，不标为Java 21新特性 |
| var | Java 10 | 基础达标后短对比；局部变量类型推断，不是动态类型；可继续写显式类型 |
| switch表达式 | Java 14 | 先会熟悉的分支，再对比返回值表达式，不与模式匹配混称 |
| 文本块 | Java 15 | 菜单稳定后选做多行文本改写，第一周不要求 |
| Record | Java 16 | 普通类学会后，在DTO/商品摘要场景比较；不当需要常规setter的万能实体 |
| switch模式匹配、Record Patterns | Java 21 | Web/框架阶段小例子，能认识即可，不作Boot前置 |
| 虚拟线程 | Java 21 | 教师选做演示大量等待型任务；不宣称能让CPU计算自动加速 |

本项目默认不开启预览功能。特性的正式版本与适用边界以官方资料核对；校内Java 8作业不使用这些超出其语言级别的语法。教学排序是本稿建议，不是官方规定课时。

### 5. AI与小组协作原则

基础整合关卡通过前，仅允许AI解释概念、报错和提示，不生成提交的业务功能。通过后，每次辅助一个验收明确的小任务：先独立尝试 → 说明约束 → 审查改动 → 运行验证 → 记录采纳理由。这里不同于参考实验中“由Agent生成个人网站”的目标，不能直接照搬其代写方式。

3–4人小组前期各自练习，结对排查只给提示；基础关卡通过后维护团队主仓库，轮换实现、测试审查、集成角色。每人每周仍需一项可解释的个人改动或独立练习，不能固定只做文档。

## 四、实训内容与步骤

### 1. 总体学习安排：16周推荐讨论路线

每人每周暂按两次75分钟指导、150–180分钟自主练习、30分钟全组验收，共5.5–6小时。第一周练习拆成三个60分钟段，总计6小时。包含记录与互审，不追加每日站会。以下周次不是实际日期，是否采用16周由教师确认。

### 3. 第一周：控制台菜单启动

**本周功能边界：**1输入商品名称并回显，2显示固定商品示例，0退出。名称回显不是发布成功；固定示例不是动态商品列表。第一周不要求商品类、集合、价格、数据库、Maven或新语法。

教师提供Main启动结构与必要的Scanner调用范例；学生自己完成分支、循环和退出。按字符串读取菜单，去首尾空白后判断1/2/0，其他输入提示未知选项；暂不同时引入整数解析和异常体系。

| 安排 | 时长 | 活动与产物 |
|---|---|---|
| 指导A，建议D1 | 75分钟 | 演示与诊断、环境、字符串输入、单次分支 |
| 自主练习A，建议D2 | 60分钟 | 单次输入1/2/0得到不同提示，abc/9提示无效 |
| 指导B，建议D4 | 75分钟 | while循环、退出、名称回显、空输入、独立变式、Git |
| 自主练习B，建议D5 | 60分钟 | 连续操作、正常退出、空/未知输入提示 |
| 自主练习C，建议D6 | 60分钟 | 自测、修复、说明、个人验收准备 |
| 全组验收，建议D7 | 30分钟 | 每人约5分钟运行/解释/小改，其余共性反馈 |
| 合计 | 360分钟 | 每人6小时，已含记录，不额外增加材料任务 |

**实训步骤1：项目认识、基础诊断与环境确认（30分钟，指导A前半段）**

（1）用5分钟演示三项菜单，说明本周只做启动练习。

（2）用10分钟独立诊断：输出文字和字符串变量；按给定值显示不同提示；循环输出三次并解释停止条件。

（3）用15分钟确认当前项目JDK和运行方式，实际运行最小程序；校内Java 8环境保留。不要求数据库、Maven或远程账号已配置。

**实训步骤2：输入、单次判断与独立变式（45分钟，指导A后半段）**

（1）10分钟：修改变量和输出文字；20分钟：读取整行、按1/2/0判断，教师统一选一种熟悉写法。

（2）10分钟：收起完整范例，让每人修改一个临时选项或提示并运行；5分钟说明自主练习A。

（3）自主练习A只要求单次选择，不要求循环。每人发一次“做了什么、卡在哪、下一步”，卡住20–30分钟及时求助。

**实训步骤3：循环、退出与名称输入（75分钟，指导B）**

（1）10分钟复盘；20分钟从“一次就结束”引出while和退出条件。

（2）15分钟加入商品名称回显、空名称和未知选项处理；非法输入提示后回到菜单。

（3）15分钟独立做一个已讲内容的小变式，同伴只给定位提示；10分钟演示差异、暂存、提交；5分钟布置练习B/C。

（4）Git保存当前可运行版与后续真实改动，共两次有意义提交即可。不要求凑四次提交，不因账号/网络问题阻挡基础学习。

**实训步骤4：自主完成、自测与周末验收**

（1）练习B：完成三项菜单，连续操作三次再退出；修复真实问题，保存版本。

（2）练习C：按下表自测，写环境、运行方式、已完成/未完成内容；记录教师提供部分和自己完成部分。未使用AI就写“未使用”，不强制截图和录屏。

（3）验收：每人1分钟运行，2分钟解释输入/分支/循环/退出在哪里，2分钟做小改并验证。现场不用AI，不要求未教过的类、集合或数据库。

### 4. 后续实施关键点

（1）面向对象/集合阶段：先创建两件不同商品，再把多个商品加入集合；入口读取输入，业务处理规则，存储负责保存查询。先会用再解释选择，不一次铺开所有设计模式。

（2）数据库阶段：Java调用通过参数绑定传值，不拼接用户输入；资源及时关闭。事务统一用“仍在售商品标记已售 + 写成交记录”，教师设置第二步失败，验证第一步也回滚；重复成交拒绝。

（3）Web阶段：教师给最小HTTP适配骨架，学生把既有Service接入；使用同一组发布/查询/错误用例。反射注解控制在短演示或60–90分钟选做，不做完整MVC。

（4）Boot阶段：先迁装配和入口，后换持久化实现，不同时重写所有业务。Spring事务从受管理Service的外部调用进入，示范生效边界；沿用原生阶段的回滚用例。

（5）协作与AI：每周两次简短反馈，卡点及时求助；基础关卡后轮换角色。Agent一次一个任务，先列验收，再看差异、跑测试，最终由本人解释。

## 八、思考题

1. 第一周程序为什么需要循环？未知选项为什么不能和退出共用一条处理路径？
2. 为什么先把一个商品名称放进变量还不够？当要保存多个名称时，数组/集合解决了什么问题？
3. 类和对象有什么区别？两件商品的字段为何应属于各自对象，而不是几组彼此靠位置对应的数组？
4. 方法、封装和职责拆分分别解决什么问题？把main压到很短是否就代表设计好？
5. 为什么存储操作可以放在接口后面？从内存改为数据库时，哪些业务规则不应跟着重写？
6. Maven与Git分别负责什么？为什么看到“能在我的电脑运行”还不足以说明项目可复现？
7. 参数绑定、资源关闭和事务分别避免哪些问题？标记已售成功但成交记录失败时应发生什么？
8. HTTP和JSON有何区别？一次发布请求如何走到Service、数据库，再返回响应？
9. 反射和注解在短路由示例里分别做了什么？为什么本课程不要求先手写完整MVC才能学习Spring？
10. 手工通过构造器传入依赖，与Spring负责提供依赖有什么相同和不同？如何判断自己是在理解DI而不是背注解？
11. var、文本块、Record是否都首发于Java 21？为什么先学普通类，再比较Record？
12. AI输出能运行就可以接受吗？当不能解释、没有边界测试或使用了不匹配的版本时，应怎样处理？
