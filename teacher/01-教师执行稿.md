# 第一节线上 Java 基础补齐课：教师执行稿

## 开课前

- 提前一天发送 `student` 文件夹和课前检查清单。
- 要求学生把项目解压到纯英文或容易找到的目录。
- 运行 `../tools/verify.ps1`，确认本机环境和答案行为。
- 将学生姓名填入 `06-学生能力矩阵.csv`。
- 腾讯会议聊天区约定状态码：`1` 完成，`2` 有问题但可跟上，`3` 阻塞，`C` 编译错误，`R` 结果错误，`E` 环境错误。

## 0-6 分钟：运行检查

教师口令：

> 打开 `student/starter`，先不要改代码。编译并运行后，在聊天区回复：`1 已看到菜单`、`2 有问题但能继续` 或 `3 没有运行起来`。如果是错误，再补一个字母：`C`、`R` 或 `E`。

处理原则：

- 同一问题达到 3 人，统一共享屏幕处理，最多 3 分钟。
- 个别环境问题先进入教师共享环境观察，课后单独补环境。
- 不在此阶段讲 IDE 功能或 JDK 历史。

检查点：每人至少看到一次菜单，或教师已明确记录其环境阻塞。

## 6-12 分钟：只演示行为

运行教师答案，不展示答案源代码，依次输入：

```text
1
2
key
2

9
0
```

提问：

1. 程序接收了哪些输入？
2. 哪些操作后菜单应该再次出现？
3. 空关键字为什么不能显示全部物品？
4. 退出和程序崩溃有什么区别？

板书行为链：`输入 -> 分支 -> 执行任务 -> 验证结果 -> 继续或退出`。

## 12-24 分钟：六题微诊断

使用 `02-微诊断答案与分层.md`。每题 1-2 分钟，只收答案，不公布排名。

快速记录：

- 0-2 题清楚：红色脚手架；
- 3-4 题清楚：黄色脚手架；
- 5-6 题清楚：绿色脚手架。

不要按总人数平均分组。分层依据是当前可观察能力。

## 24-39 分钟：TODO 1，输入与分支

让学生先找到：

- `Scanner` 创建位置；
- `choice` 读取位置；
- `if / else if / else` 四条路径；
- TODO 1 的占位输出。

任务：用 `for-each` 替换 TODO 1 占位输出，逐项显示 `items`。

教师只提供最小提示：

```java
for (String item : items) {
    System.out.println(item);
}
```

验证输入：`1`。追问：循环每一轮的 `item` 分别是什么？

## 39-51 分钟：TODO 2，循环与退出

先让学生观察骨架为什么选择一次就结束，再定位：

```java
if (running) {
```

任务：将控制结构改为能重复执行的循环，同时保留输入 `0` 时的 `running = false`。

验证序列：`1 -> 9 -> 1 -> 0`。

追问：

- 如果忘记修改 `running`，会发生什么？
- 如果在任意选项后都修改 `running`，会发生什么？
- 正常退出与强制停止的可观察差别是什么？

## 51-63 分钟：方法与 List 阅读

只讲三个问题：

1. `searchItems` 接收什么？
2. 它在哪里被调用？
3. 每轮遍历时 `item` 和 `keyword` 的值分别来自哪里？

在共享屏幕逐行追踪搜索 `key`：

```text
item = 螺丝刀   -> false
item = Keyboard -> true
item = 打印纸   -> false
item = 安全帽   -> false
```

不展开对象相等性、泛型原理或方法栈。

## 63-79 分钟：TODO 3、TODO 4 与局部修改

TODO 3：补全不区分大小写的部分匹配。

```java
boolean matches = item.toLowerCase().contains(keyword.toLowerCase());
```

TODO 4：匹配成功时将 `found` 改为 `true`，使“未找到”只在确实没有结果时显示。

完成后，每人从以下四项中选一项独立修改：

- 无效输入时回显用户输入；
- 退出时增加一行总结；
- 列表输出增加从 1 开始的序号；
- 固定列表增加一项，并证明列表和搜索都能看到。

学生求助必须包含：正在完成、输入、预期、实际、错误信息、已经检查过什么。

## 79-87 分钟：五场景验证

课堂最低完成 T01、T03、T06、T07、T08。要求先写预期，再运行，不允许只填“通过”。

抽两名学生共享屏幕：一人演示成功场景，一人演示曾失败后修复的场景。教师关注其排查过程，不评价页面美观或代码行数。

## 87-90 分钟：离场票

学生填写 `student/03-自测与离场票.md` 最后一节，并提交：

- 今天能独立完成的一件事；
- 仍然卡住的一件事；
- 一个测试输入和实际结果；
- 是否需要补练。

## 课堂停止条件

达到以下状态后不再增加内容：

- 多数学生能运行综合题；
- 每人完成至少一项独立修改；
- 学生开始用输入和结果验证，而不是只看代码；
- 教师已识别需要补练的具体能力项。

提前完成时优先做现场小改、错误排查和测试补充，不加入 WorkBuddy、Git、Maven、业务类或 Java 21 特性。
