# Agent API 项目驱动学习方案：103 智能仓管 Agent

> 讨论稿 v0.1｜2026-10-16  
> 核心转向：不再以“先补完 Java 基础，再开始做项目”为顺序；先交付一个能对话、会调用仓库工具的 Agent 软件，再围绕它缺失的能力补 Java、HTTP、JSON、数据库和 Spring Boot。

## 1. 核心判断

单纯把控制台菜单做得更漂亮，仍然改变不了“学生知道自己正在练基础语法”的感觉。更合适的主线是：

> 学生第一天就拥有一个可以对话的仓库 Agent；Agent 能不能完成任务，取决于学生有没有为它写好 Java 工具。

课堂不再说：

- 今天学变量；
- 今天学循环；
- 今天学 List；
- 今天学异常。

而改成：

- Agent 听不懂物品名称，因为参数没有正确处理；
- Agent 只能看到一件物品，因为仓库工具没有遍历数据；
- Agent 找不到低库存物品，因为筛选规则没有实现；
- Agent 一遇到空数据就崩溃，因为错误处理没有实现；
- Agent 每次重启都失忆，因为数据还没有持久化。

学生补的每一个知识点，都立即变成软件的一项新能力。

---

## 2. 建议的软件：103 智能仓管 Agent

学生可以直接用自然语言提出任务：

```text
我：帮我找一下仓库里的键盘。
Agent：我找到了 2 个相关物品：机械键盘位于 C-03，备用键盘位于 C-07。
```

```text
我：哪些电子设备库存不足？
Agent：目前有 2 项低库存物品：键盘 2 个、无线鼠标 1 个。建议优先补充无线鼠标。
```

```text
我：把螺丝刀数量增加 10 个。
Agent：这是库存写入操作。请确认是否将螺丝刀从 25 调整为 35。
```

Agent 自己不直接读取或修改仓库数据，而是选择调用 Java 程序提供的工具：

- `search_inventory(keyword)`：按关键字查找；
- `list_low_stock(threshold)`：查找低库存；
- `get_item_location(itemId)`：查询位置；
- `get_inventory_summary()`：生成仓库概况；
- `adjust_stock(itemId, change)`：调整库存，后期增加人工确认；
- `create_restock_suggestion()`：结合查询结果生成补货建议。

第一周只开放只读工具，不开放真实写入。

## 3. 软件结构：Agent 是大脑，Java 是手脚

```text
学生输入自然语言
        ↓
Agent API / 模型
        ↓ 决定调用哪个工具
Java AgentGateway（教师提供）
        ↓
InventoryTools（学生逐周实现）
        ↓
InventoryService（业务规则）
        ↓
内存 List → 文件 → MySQL
        ↓
工具结果返回 Agent
        ↓
Agent 用自然语言回答学生
```

教学时用四个比喻：

- **Agent**：大脑，理解用户想做什么；
- **Tool 方法**：手，真正执行查询和修改；
- **InventoryService**：规则，决定怎样查询和修改；
- **数据存储**：记忆，决定程序重启后是否还记得。

最重要的一句话：

> AI 可以决定“要使用搜索工具”，但如果学生没有把搜索工具写好，Agent 仍然什么都做不了。

这样可以避免学生产生“有了 AI 就不需要编程”的误解。

## 4. 教师与学生的代码边界

### 教师第一周提供

为了避免第一天被 API 鉴权、HTTP、JSON 和事件循环淹没，教师提供一个能运行的项目骨架：

- `AgentClient` 接口；
- `OpenAiAgentClient` 实现；
- Agent 会话与 function/tool calling 流程；
- API 请求、响应和 JSON 解析；
- 控制台或简单聊天界面；
- `FakeAgentClient` 离线实现；
- API 密钥从环境变量读取的配置；
- 一个已经完成的示例工具，例如 `get_current_time` 或 `get_inventory_summary`；
- 基础测试和启动说明。

这些代码可以运行，但第一周不要求学生从零编写，也不把它们假装成学生掌握的内容。

### 学生第一周负责

- 修改 Agent 的身份和回答规则；
- 修改仓库示例数据；
- 完成或修复一个 Java 仓库工具；
- 运行至少三个自然语言请求；
- 记录 Agent 选择了哪个工具；
- 验证工具结果是否正确；
- 说明一次失败是 Agent 理解问题，还是 Java 工具问题。

学生第一周提交的是“仓库能力代码”，不是底层 Agent API 封装。

## 5. 第一周的最佳钩子：让 Agent 先失败

教师演示时不要先展示一个什么都正确的成品。可以安排一个可控故障：

```text
我：帮我找一下仓库里的螺丝刀。
Agent：仓库中没有找到螺丝刀。
```

但投影上同时能看到仓库数据中明明有“十字螺丝刀”。

教师问：

> 是 Agent 太笨，还是我们交给它的搜索工具有问题？

随后展示调用轨迹：

```text
Agent 选择工具：search_inventory
参数：{"keyword":"螺丝刀"}
工具返回：[]
```

学生检查 `searchInventory`，发现它可能存在以下问题之一：

- 只比较完整名称；
- 没有遍历所有物品；
- 找到后没有加入结果；
- 大小写或首尾空格没有处理；
- 错误地在第一轮循环就返回。

这时再学习字符串、循环、条件和 List，知识点就有明确用途。

## 7. 三档代码任务，避免基础差异拖垮课堂

同一个 `searchInventory` 能力提供三种任务卡。

### A 档：补一个条件

教师给出完整循环，只缺少匹配判断。学生完成：

- 获取名称；
- 判断名称是否包含关键字；
- 验证“螺丝刀”能匹配“十字螺丝刀”。

对应知识：字符串、变量、if。

### B 档：补循环和结果收集

教师给出方法签名和数据，学生完成：

- 遍历物品；
- 判断匹配；
- 把结果加入 List；
- 返回全部结果。

对应知识：循环、List、方法返回值。

### C 档：独立设计工具

学生独立实现：

- 空关键字处理；
- 忽略大小写与首尾空白；
- 多条结果；
- 最大结果数量；
- 编写测试。

对应知识：字符串处理、集合、边界条件和测试。

学生最后展示的是同一种 Agent 能力，但所完成的代码深度不同，不需要所有人被迫复制同一份答案。

## 8. 第一周每日任务重新设计

| 教学日 | Agent 能力任务 | 被需要时才学习的 Java 知识 | 可展示成果 |
|---|---|---|---|
| 周日 | 运行 Agent，修复 `search_inventory` | 字符串、if、循环、List 的最小使用 | Agent 能找到物品 |
| 第 2 天 | 增加 6 条自己的仓库数据 | 变量、对象或教师给定的数据结构 | Agent 能认识个人数据 |
| 第 3 天 | 增加 `list_low_stock` | 遍历、比较、筛选、方法 | 自然语言查询低库存 |
| 第 4 天 | 处理空关键字和不存在物品 | null/空值、分支、错误结果 | Agent 不再胡乱回答 |
| 第 5 天 | 增加工具调用日志 | 字符串格式、时间、方法职责 | 能解释 Agent 做了什么 |
| 第 6 天 | 完成 4 个验证场景和 Git 提交 | 测试思维、版本记录 | 运行记录与修复对比 |
| 第 7 天 | 90 秒 Agent 能力演示 | 复盘、表达、现场修改 | 一次真实对话演示 |

第一周不要求学生从零实现 HTTP 客户端、JSON Schema、会话状态和复杂 SDK 调用。它们先作为可运行黑盒，到后续对应阶段再逐步打开。

## 9. 后续知识不再按章节，而按 Agent 能力解锁

| Agent 遇到的问题 | 需要补的知识 | 软件升级 |
|---|---|---|
| 只能处理一条数据 | 循环、List | 能搜索全部物品 |
| 不知道物品有哪些字段 | 类、封装、构造器、Record 对比 | 建立 Item 模型 |
| 方法越来越乱 | 方法、接口、职责拆分 | Tool / Service / Repository 分层 |
| 遇到空输入或坏数据崩溃 | 异常、校验、错误结果 | Agent 能解释失败原因 |
| 每次重启库存消失 | 文件、JDBC、SQL | 获得长期记忆 |
| Agent 不知道怎样访问数据库 | Repository 模式 | 工具与存储解耦 |
| 想让 C# 或网页使用 | HTTP、JSON、REST | 对外提供 API |
| 接口越来越多 | Spring Boot、依赖注入 | 正式服务化 |
| Agent 可能误操作库存 | 权限、确认、幂等、审计日志 | 安全写入工具 |
| Agent 有时回答不稳定 | 测试用例、评测、日志 | 建立 Agent 验收集 |

学生会感觉是在不断给软件增加能力，而不是在按目录补课。

## 10. Agent API 的教学实现建议

### 推荐边界

第一阶段使用“Agent + function tools”即可，不上多 Agent、浏览器控制、代码执行、MCP 和复杂工作流。

核心循环只有四步：

1. 用户提出自然语言任务；
2. Agent 选择 Java 工具并给出结构化参数；
3. Java 执行工具，返回结构化结果；
4. Agent 根据结果回答用户。

### Java 落地

教师将官方 Java SDK 或 HTTP 封装隐藏在 `AgentClient` 后：

```text
AgentClient
├── OpenAiAgentClient   真实在线调用
└── FakeAgentClient     离线固定调用
```

课堂默认优先使用真实调用制造体验，但必须保留 Fake 模式。没有网络、额度、密钥或 API 暂时失败时，学生仍然可以学习工具契约和 Java 业务代码。

### 为什么不让学生第一天直接写 SDK 调用

第一天若同时出现以下内容，会完全遮住教学目标：

- API Key；
- Maven 依赖；
- HTTP 请求；
- JSON Schema；
- 序列化；
- 会话状态；
- 异步事件；
- function call 与 tool result 的往返。

这些都值得学习，但应当在学生先理解“Agent 为什么需要 Java 工具”之后再逐层打开。

## 11. API 密钥、成本和安全边界

- API 密钥不写进 Java 源码、不提交 Git、不截图发群；
- 学生端优先访问教师控制的本地代理或使用各自环境变量；
- 不在客户端软件中内置长期密钥；
- 第一周仅开放只读工具；
- 库存修改、删除和批量操作必须增加显式确认；
- 工具参数必须在 Java 端再次校验，不能因为参数来自 Agent 就默认可信；
- 使用虚构仓库数据，不输入真实人员、资产、账号和内部位置；
- 准备调用次数上限和 FakeAgent 离线模式，避免课堂受网络或额度影响。

## 12. 第一周验收不再问“学了哪些语法”

每人演示：

1. 向 Agent 提出一个仓库问题；
2. 指出 Agent 选择了哪个工具；
3. 展示工具收到的参数；
4. 说明自己修改了哪段 Java；
5. 展示修复前和修复后的差异；
6. 现场修改一条规则并再次验证。

建议验收问题：

- “查找所有名称中包含‘键盘’的物品。”
- “找出数量小于 5 的电子设备。”
- “查询一个不存在的物品。”
- “输入一个空关键字。”
- “尝试让 Agent 修改库存，确认它不会无提示执行。”

评价重点：

- 工具结果是否正确；
- 能否分清 Agent 判断和 Java 执行；
- 能否解释并修改自己的代码；
- 是否验证失败情况；
- 是否保护危险操作。

不以回答文风多漂亮作为主要成绩。

## 13. 推荐的第一周成果名称

不叫“控制台仓库查询器 V0”，改成：

> **103 智能仓管 Agent · Tool Pack 01**

第一周结束时，学生可以说：

> 我的 Agent 已经能调用 Java 搜索工具查找物品、处理不存在的结果，并展示低库存信息。它目前只能读数据，下周我要给它增加规范的物品模型和更多工具。

这比“我这周学习了 if、while 和 ArrayList”更容易形成作品感，但底层实际覆盖的仍然是这些基础能力。

## 14. 建议的下一步交付物

确认采用这条路线后，应立即制作四份可运行材料：

1. **教师演示工程**：真实 Agent 调用 + 两个完整工具；
2. **学生骨架工程**：Agent 已接通，`search_inventory` 留三档 TODO；
3. **FakeAgent 离线工程**：无密钥也能模拟工具调用；
4. **周日教师逐字稿与学生任务卡**：围绕“发现失败—追踪工具—修复—重新提问”编写。

原“控制台菜单 V0”可以保留为 Agent 无法使用时的应急底层练习，但不再作为课堂主叙事。
