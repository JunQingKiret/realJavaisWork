# 10 人线上 Agent 协作与 Java 项目指导课程规划

> 讨论稿 v0.1｜2026-10-16  
> 授课形式：腾讯会议线上指导  
> 学生规模：10 人  
> 技术主线：CodeArts Agent + Agent Lab Lite + FakeAgent + 可替换云 API  
> 建议周期：16 周；每周 1 次同步指导 + 课后个人任务  
> 本稿先用于确认课程结构、平台、课时和评价方式，不是最终学生讲义。

---

## 1. 我希望把这门课教成什么样

我不准备把这门课教成“老师讲完 Java 语法，学生照着敲一遍”，也不准备把它教成“把任务交给 Agent，谁生成得快谁就完成了”。

我希望学生经历一个完整过程：

1. 先看到 Agent 能快速生成内容和软件；
2. 再发现它可能虚构事实、误解要求、使用错误工具；
3. 学会查看计划、工具调用、参数、数据来源和代码改动；
4. 通过 Java 为 Agent 增加真实能力；
5. 用测试和事实核验判断结果是否可靠；
6. 最后交付一件“人定义目标、Agent 协助、程序提供能力、人负责验收”的作品。

这门课不回避基础知识，但基础知识不以章节目录出现，而以软件遇到的真实问题出现：

- Agent 搜索不到物品，需要字符串、判断和循环；
- Agent 只能返回第一条结果，需要 List 和方法返回值；
- Agent 一重启就失忆，需要文件、JDBC 和数据库；
- Agent 无法被网页或 C# 使用，需要 HTTP、JSON 和 REST；
- Agent 的工具越来越混乱，需要接口、分层和 Spring Boot；
- Agent 可能乱改数据，需要权限、确认、日志和测试。

最终目标不是让学生背出更多术语，而是让他们能够回答：

> Agent 帮了什么？它为什么可能错？程序怎样约束它？我怎样证明最终结果可信？

## 2. 课程技术栈收敛

### 2.1 学生唯一主要桌面工具

**CodeArts Agent**。

使用方式分成两种：

- **Space 模式**：需求整理、内容生成、文档分析、Agent 协作和作品设计；
- **IDE 模式**：Java 代码、测试、Git、终端、Diff 和浏览器预览。

不要求学生长期同时使用 WorkBuddy 和 ZCode，减少账号、客户端和操作规则切换。

### 2.2 唯一课程项目

**Agent Lab Lite**。

它不是第二套桌面软件，而是学生在 CodeArts 中打开、运行和逐周完善的项目。

```text
Agent Lab Lite
├── 任务目标与约束
├── Agent 内容生成
├── Java 工具调用
├── 工具参数与结果轨迹
├── 事实核验
├── 初稿与终稿对比
└── API 模式与调用统计
```

### 2.3 三种运行模式

```text
AgentProvider
├── FakeAgentProvider   默认教学模式
├── CloudAgentProvider  自定义 API 模式
└── LocalAgentProvider  本地模型备用模式
```

界面必须明确显示当前模式：

- `FAKE`：教师预设、结果稳定；
- `CLOUD`：真实云模型，结果可能变化；
- `LOCAL`：本地模型。

云端失败后不得静默伪装成真实回答。若降级，界面必须明确提示“已切换到模拟模式”。

### 2.4 ZCode 邀请权益的定位

ZCode 邀请所得权益不直接成为课程基础设施，只作为“第一次接入真实云模型”的实验资源。

接入前必须确认：

1. 权益是通用 API 余额、Coding Plan，还是客户端体验额度；
2. 是否能生成个人 API Key；
3. 是否允许普通 Agent 应用调用；
4. 有效期和调用限制；
5. 是否需要实名认证或其他账号条件。

若属于通用 API 权益，则接入 `CloudAgentProvider`；若只属于 Coding Plan 或 ZCode 客户端权益，则用于一次 Coding Agent 对比，不承诺能接入 Agent Lab Lite。

## 3. 10 人线上教学组织

### 3.1 基本组织

10 名学生分成两个长期学习队：

- A 队：5 人；
- B 队：5 人。

采用两个大队是为了适配腾讯会议免费版和专业版最多创建 2 个分组讨论室的限制。若学校已有教育版、商业版或企业版，可改为 5 组 × 2 人。

每个 5 人队设置五个轮换角色：

| 角色 | 课堂职责 |
|---|---|
| 驾驶员 | 共享屏幕、运行项目、输入命令 |
| 代码观察员 | 检查 Java 方法、Diff 和测试结果 |
| Agent 观察员 | 记录计划、工具名称、参数和回答 |
| 事实核验员 | 查找虚构、冲突和缺少证据的内容 |
| 汇报员 | 记录小组结论，回主会场展示 |

每次线上课至少轮换一次；连续两周不得由同一人担任驾驶员或汇报员。

### 3.2 个人掌握不能用团队作品代替

团队完成作品，但每名学生仍须完成：

- 1 次个人真实提交；
- 1 份个人离场票；
- 1 个个人验证场景；
- 1 次 2 分钟以内的独立解释或现场小改；
- AI/API 使用记录。

随机抽查时，任何成员都应能指出：

- Agent 调用了哪个工具；
- 工具对应哪个 Java 方法；
- 输入、输出和失败场景是什么；
- 本人完成了哪一项修改。

## 4. 腾讯会议平台方案

### 4.1 推荐方案：教师专业版 + 两个 5 人讨论室

建议由教师主持账号使用腾讯会议专业版，学生作为普通参会者进入。

原因：

- 单场课程不受 40 分钟限制；
- 10 人规模远低于 100 人上限；
- 可以使用两个分组讨论室；
- 适合 A、B 两队竞争和轮换；
- 不需要为 10 名学生购买高级账号。

当前官网公开价格为按月 98 元/主持账号，或按年折算每月 82.34 元；实际以购买页面为准。专业版最多仍为两个分组讨论室，因此本方案采用两个 5 人队，而不是五个双人讨论室。

### 4.2 完全免费方案：两场 40 分钟会议 + 10 分钟异步离场

如果暂不购买专业版，可把原来的 8:10–9:50 切成：

| 时间 | 安排 |
|---|---|
| 8:10–8:50 | 腾讯会议 A：演示、找错、讲解任务 |
| 8:50–9:00 | 离线休息、重新连接、独立启动项目 |
| 9:00–9:40 | 腾讯会议 B：分组实践、展示、复盘 |
| 9:40–9:50 | 会后表单/群内个人离场票 |

免费版单场当前限制为 40 分钟，因此预先建立两个会议链接，不在课堂上临时创建。

### 4.3 理想方案：学校教育版或商业版

若学校已有对应授权，可创建 5 个双人讨论室，教师依次巡组。这是个别指导最充分的方案，但不建议仅为本次 10 人试点直接购买至少 6 个商业版高级账号。

### 4.4 腾讯会议功能使用约定

- 入会名称统一为 `A1-姓名`、`B1-姓名`；
- 教师讲解阶段仅主持人共享屏幕；
- 学生展示阶段按顺序开放共享；
- 公开聊天仅用于问题编号、状态和链接；
- 需要集中注意时关闭私聊；
- 使用投票做快速判断；
- 使用批注让学生圈出 Agent 输出中的无证据事实；
- 分组讨论结束前设置 60 秒倒计时；
- 主持人每个讨论室停留 4–5 分钟，不长期留在某一组；
- 录制仅用于教师讲解和自愿展示，涉及学生声音、画面和分组讨论时先获得明确同意。

## 5. 每周固定时间模型

建议每周固定总投入为 4.5–5.5 小时/人：

| 活动 | 时间预算 |
|---|---:|
| 腾讯会议同步指导 | 100 分钟 |
| 个人实现任务 | 90–120 分钟 |
| 小组异步互审 | 30 分钟 |
| 测试、记录、Git 提交 | 45–60 分钟 |
| 汇报准备 | 20–30 分钟 |
| **合计** | **285–340 分钟** |

同步课的目标比例：

- 教师单向讲解不超过 25 分钟；
- 学生观察与判断不少于 20 分钟；
- 学生实际操作不少于 35 分钟；
- 展示、互评和复盘不少于 15 分钟；
- 留 5 分钟处理技术缓冲。

## 6. 16 周量化路线

### 第一阶段：先认识 Agent，而不是先背语法（第 1–3 周）

| 周次 | 核心问题 | 项目成果 | 知识需求 |
|---|---|---|---|
| 1 | Agent 为什么会生成看似正确但没有证据的内容？ | 数字导览初稿、局限清单、一次工具修复 | 字符串、判断、循环最小使用 |
| 2 | Agent 为什么依赖工具？ | 搜索、低库存和位置工具 | 类、对象、List、方法 |
| 3 | 如何稳定测试 Agent 软件？ | AgentProvider 接口、FakeAgent 和测试场景 | 接口、多态、异常、测试替身 |

阶段验收：

- 每人能区分模型回答、工具结果和真实数据；
- 每人至少修复一个 Java 工具；
- 每组至少有 6 个可重复验证场景；
- 没有真实 API 也能完整运行演示。

### 第二阶段：接入真实模型并认识不稳定性（第 4–6 周）

| 周次 | 核心问题 | 项目成果 | 知识需求 |
|---|---|---|---|
| 4 | 如何安全接入自定义 API？ | CloudAgentProvider | 环境变量、HTTP、JSON、DTO |
| 5 | API 超时、401、429 怎么办？ | 超时、错误提示、显式降级 | 异常、重试、状态码、日志 |
| 6 | 如何证明改动没有破坏旧功能？ | Maven、Git、基础自动测试 | 构建、版本管理、断言 |

阶段验收：

- API Key 不出现在仓库、截图和日志；
- 每人完成一次真实 API 调用；
- 每组演示一次云端失败后显式切换 FakeAgent；
- 每组至少 10 个自动或半自动验证场景；
- 真实 API 成功不是及格条件，正确处理失败才是。

### 第三阶段：为 Agent 建立可靠数据与服务（第 7–11 周）

| 周次 | 核心问题 | 项目成果 | 知识需求 |
|---|---|---|---|
| 7 | 程序重启后怎样保留数据？ | JDBC 持久化 | SQL、JDBC、资源关闭 |
| 8 | 多步库存变更失败怎么办？ | 事务与回滚 | 事务、业务规则 |
| 9 | 其他客户端怎样调用？ | HTTP/JSON API | REST、请求响应 |
| 10 | 怎样避免手工组装所有对象？ | Spring Boot 初次迁移 | 配置、构造器注入、分层 |
| 11 | 工具、服务和存储怎样解耦？ | Tool/Service/Repository | 接口、依赖注入、测试 |

阶段验收：

- 数据重启后仍存在；
- 失败操作不留下半完成数据；
- C#、网页或API客户端至少一个能调用；
- Agent工具不直接拼SQL；
- 关键业务有测试。

### 第四阶段：把 Agent 变成可交付软件（第 12–16 周）

| 周次 | 核心问题 | 项目成果 |
|---|---|---|
| 12 | 如何约束危险操作？ | 权限、人工确认、审计日志 |
| 13 | 如何检查内容事实？ | 事实核验器、证据标记 |
| 14 | 如何评价 Agent，而不是凭感觉？ | 固定评测集和结果统计 |
| 15 | 如何让别人运行？ | 配置说明、打包、部署或本地启动脚本 |
| 16 | 如何证明是自己掌握的？ | 最终演示、现场修改、个人答辩 |

最终每组交付：

- 1 个可运行的 Agent Lab Lite；
- 1 套 Fake/Cloud 双模式；
- 5 个以上 Java 业务工具；
- 15 个以上验证场景；
- 1 份使用说明；
- 1 份 Agent 局限与安全说明；
- 1 次 8 分钟小组演示；
- 每人 3 分钟个人答辩和 1 次现场修改。

## 7. 第一次线上课详细方案

### 7.1 课前 48 小时准备

教师准备：

- CodeArts 安装和登录说明；
- Agent Lab Lite 压缩包或仓库；
- FakeAgent 场景；
- 两个腾讯会议链接（免费方案时）；
- A、B 队名单和本次角色；
- 三个投票；
- 一张“Agent 输出事实核验表”；
- 云 API 不作为本节课依赖。

学生在课前完成：

- 安装并登录 CodeArts；
- 准备 JDK；
- 下载并打开项目；
- 成功运行 FakeAgent；
- 加入一次 5 分钟设备测试；
- 截图提交“界面 + Fake 模式标识”；
- 确认没有把 API Key 写入项目。

课前通过门槛：10 人中至少 8 人完成；未完成者在课前进入单独技术排障，不占正式课程时间。

### 7.2 腾讯会议投票

提前创建三项：

1. “Agent 写得很流畅，是否说明内容可信？”
2. “错误回答主要可能来自哪里：需求、模型、工具、数据、都有可能？”
3. “Agent 是否可以在没有确认的情况下修改库存？”

第一项在开场前投，第三项在结尾再投，用前后变化观察学生认知。

### 7.3 100 分钟流程

| 时间 | 环节 | 教师行为 | 学生产出 |
|---|---|---|---|
| 8:10–8:15 | 状态确认 | 点名、运行投票1、检查项目状态 | 聊天区发绿/黄/红状态 |
| 8:15–8:23 | Agent 快速生成 | 在 CodeArts Space 生成仓库数字导览 | 记录第一印象 |
| 8:23–8:33 | 全班找茬 | 开放互动批注，圈出虚构和无证据内容 | 每人至少指出1处问题 |
| 8:33–8:42 | 揭开结构 | 展示需求→计划→工具→Java→结果→内容 | 完成问题归因 |
| 8:42–8:50 | 发布任务 | 演示 Agent Lab Lite 的错误搜索场景 | 明确分组任务 |
| 8:50–9:00 | 休息/重连 | 免费方案切换会议；专业版正常休息 | 启动个人项目 |
| 9:00–9:05 | 分组启动 | A/B 队进入讨论室，教师巡视 | 分配角色 |
| 9:05–9:20 | 第一次任务 | 修复或解释 `searchInventory` | 修复前后运行结果 |
| 9:20–9:23 | 角色交换 | 提醒换驾驶员和观察员 | 第二人接管 |
| 9:23–9:35 | 第二次任务 | 增加低库存判断或事实核验规则 | 1项能力扩展 |
| 9:35–9:42 | 回主会场 | 两队各展示3分钟，教师点评 | 初稿/终稿或结果对比 |
| 9:42–9:47 | 安全收尾 | 演示“清空库存”请求，运行投票3 | 说明为何要人工确认 |
| 9:47–9:50 | 个人离场票 | 发布课后任务 | 每人独立提交3句话 |

### 7.4 第一次课的量化结果

课堂结束时应得到：

- 10 份个人找茬记录；
- 2 份小组故障分析；
- 至少 2 个能运行的 Java 修复版本；
- 每队 1 次 Agent Lab 演示；
- 10 份个人离场票；
- 不要求任何学生完成真实云 API 配置。

个人离场票只回答：

1. Agent 今天做得最好的一件事是什么？
2. 它最不可信的一处是什么？
3. 下次我准备为它增加哪一项真实能力？

## 8. 自定义 API 环节的量化安排

建议放在第 4 周，不提前到第一周。

### 第 4 周课前

- 确认邀请权益类型；
- 每人拥有自己的账号和密钥，不共享；
- `.env`、本地配置和环境变量加入忽略规则；
- 教师准备无密钥的 Fake 模式；
- 每组准备 1 个可验证提示。

### 课堂调用预算

| 调用者 | 真实云调用上限 |
|---|---:|
| 教师演示 | 3 次 |
| 每个 5 人队 | 3 次 |
| 每名学生个人验证 | 1 次 |
| **全班单节上限** | **19 次** |

超过上限切回 FakeAgent，不通过反复重试追求“完美答案”。

### 每次调用必须留下的记录

- 时间；
- 模式与模型名称；
- 请求目标摘要；
- 是否调用工具；
- 成功/401/429/超时；
- 输出中有哪些事实；
- 哪些事实已验证；
- 本次是否消耗个人权益。

### 真实 API 验收

不是“调用成功”就通过，而是：

- 密钥安全；
- 能解释请求和响应；
- 失败时有明确提示；
- 不静默切换模式；
- 可以使用 FakeAgent复现测试；
- 能比较真实模型与固定模拟结果的区别。

## 9. 评价体系

每阶段按 100 分评价：

| 维度 | 分值 | 观察内容 |
|---|---:|---|
| 问题与需求理解 | 15 | 能指出目标、受众、约束和验收条件 |
| Java/工具贡献 | 30 | 有本人完成的可运行代码或测试 |
| 事实核验 | 20 | 不把流畅回答当成正确答案 |
| Agent协作过程 | 15 | 会看计划、参数、Diff，不盲目接受 |
| 安全与记录 | 10 | 密钥、权限、日志和来源处理正确 |
| 独立解释与现场修改 | 10 | 能口述并完成小改 |

硬门槛：

- API Key 泄漏：该阶段安全项不通过，先撤销密钥再补验收；
- 无个人贡献：团队作品不计个人通过；
- 无验证只展示结果：最高不超过 60 分；
- 删除测试或伪造运行结果：退回重新完成；
- 真实 API 不可用但 Fake 模式、错误处理和解释完整：不扣基础分。

## 10. 线上课堂状态与求助规则

聊天区统一使用：

- `1` 或 🟢：已完成，可以继续；
- `2` 或 🟡：有问题但还能进行；
- `3` 或 🔴：阻塞，需要教师进入讨论室；
- `T`：测试失败；
- `E`：环境问题；
- `A`：Agent/API问题。

求助模板：

```text
组别/姓名：
想做什么：
实际发生什么：
错误信息：
已经试过什么：
当前使用 FAKE / CLOUD / LOCAL：
```

教师处置阈值：

- 同一问题出现 3 人以上：回主会场统一讲 3 分钟；
- 单组阻塞超过 5 分钟：先切 Fake 模式，再课后排 API；
- 云请求 60 秒无结果：取消并切 Fake；
- 课堂剩余不足 10 分钟：停止增加功能，转入验证和记录；
- 课前 3 人以上环境未完成：正式课全部使用教师共享环境，不临时全班安装。
