# 原方案优化对照与待讨论事项

> **v0.2 基础判断更新（2026-10-12）**：教师补充学生目前主要会基础语法，尚不能独立完成类+集合+输入的小程序。因此，下文 v0.1 中第一周完整 V0、第 8 周进入 Boot 等安排不再是当前执行建议。当前第一周见《第一周教学大纲》v0.2；总体推荐讨论路线见《基础优先总体学习安排》，16 周尚待确认。
>
> 本轮变化：第一周只做输入/循环菜单；第 2–4 周逐步过方法、对象、集合；第 5–6 周补职责/接口/异常/Maven；通过个人关卡后再推进。每周课时和总周期尚待教师确认。下文保留作为初轮对照，不将学生列出的技术内容视为已掌握。

> 讨论稿 v0.1｜2026-10-12｜不覆盖教师原稿。资料编号对应《Java8到Java21特性地图与资料》。

## 1. 总体判断

建议保留：12 周、3–4 人小班、校园二手交易平台、V0–V6 迭代、可视化 Git、分阶段 AI 和代码讲解。

建议调整的不是“多加技术”，而是“减少重复、控制范围、增加个人验证”。原稿最需要处理的风险是：基础复习重复校内课程、框架前置阶段过长、第一周同时装太多工具，以及小组项目无法说明每个人都掌握了什么。

## 2. 逐项对照

| 原稿安排 | 建议微调 | 原因与落地方式 |
|---|---|---|
| “掌握 Java 21 基础语法与面向对象核心” | 改为“巩固 Java 8 基础，并能在 JDK 21 上解释和使用常用新特性” | 明确这是拓展课，不从变量开始重教；第一周先做 15 分钟诊断 |
| V0 从零构建 | 每人独立做 V0，以项目复用已学知识 | 基础薄弱者补菜单与方法；基础较强者补测试场景，而不是抢跑学框架 |
| 第一周必须 Maven 验证正常 | 第一周只确认 JDK、编辑器、Git；第 4 周引入 Maven | 避免环境配置占满课时；Maven 可由教师提前准备但不作为第一周验收项 |
| 一开始安装 MySQL、Postman、AI Agent | 按需分周安装；数据库第 4 周、API 工具第 6 周 | 降低首次启动成本；AI 工具不绑定特定收费产品 |
| 商品存“数组/ArrayList” | 默认最小 Product 普通类 + ArrayList，统一一种实现 | 不用三组平行数组制造同步问题；集合第一周会用即可，第 3 周再解释选型和泛型 |
| 第一周完全不出现对象，第二周 OOP | 最小数据对象可先使用；第二周重构的是职责和依赖 | OOP 的价值不只是把字段包成类；未学类的学生拿教师提供的薄脚手架 |
| 第一周讲 var 与文本块 | 文本块用于菜单；var 限 5 分钟对比、可选使用 | 新语法服务于需求，不把“语法更短”当成主要学习成果 |
| 第 2 周 Record 与 OOP 同时出现 | 先普通类，后用 Record 表示商品摘要或请求数据 | Record 是数据载体，组件字段 final，但引用的对象并不自动深度不可变；不当万能实体 [S2] |
| 第 3 周异常、第 4 周集合 | 调整为第 3 周集合/接口/异常，第 4 周工程化和测试 | 先明确存储边界，再用异常表达规则；Java 8 的 Lambda/Stream 只按需复习 |
| “增强 switch” | 明确分成 Java 14 的 switch 表达式与 Java 21 的 switch 模式匹配 | 两者不是同一项特性，不在菜单课里捆绑教授 [S1] |
| 第 7 周把虚拟线程作为 HTTP 核心 | 第 6–7 周原生 API 必做；虚拟线程为教师演示/选做 | 先搞懂请求、响应与 JSON；虚拟线程不等于 CPU 计算加速，也不会让共享变量自动安全 [S4] |
| 第 9 周“迷你 MVC 框架” | 第 7 周做有上限的“注解路由实验”，约 60–90 分钟 | 只做显式注册的控制器、运行时注解读取、方法调用；不实现完整 MVC/容器/扫描器 |
| V5 必须代理 | 动态代理移为教师演示或选做 | AOP 可在 Spring 阶段用横切需求理解，不要求先手写代理框架 |
| 第 10 周才进入 Spring Boot | 第 8 周开始迁移，第 8–12 周共 5 周 | 保留原生经历，但给 DI、MVC、MyBatis、验证与交付更多时间 |
| Spring Boot 3.2+ | 新开课暂选 Java 21 + Boot 4.1.x + MyBatis Starter 4.0.x；开课前验证具体补丁 | Spring 在 2026-06-25 宣布 3.5.x 最后一次 OSS 发布；3.5.x + Starter 3.0.x 只作为已有教材的本地对照备选，不混用两代依赖 [S6][S12][S13] |
| AI 按版本完全开放/关闭 | 保留分阶段理念，增加个人能力门槛 | 能独立解释和修一个小错误后才扩大范围；Agent 每次只改一个有验收标准的任务 |
| 第一周 main ≤ 20 行 | 改成 main 只做启动，方法职责清楚；行数是提醒而非扣分硬门槛 | 避免为凑行数把逻辑藏进更难读的方法 |
| 提交至少 4 次、多个截图 | 保留有意义提交，减少截图，优先可运行仓库与现场演示 | 防止“交材料”代替学习；录屏与现场口述二选一 |
| 每日文字站会 | 每周两次简短进度；卡住 20–30 分钟即可求助 | 更适合课外活动，避免形成额外日常负担 |

### 版本决策的重要补充

按 2026-10-12 的时间核对，Spring Boot 3.5.x 已被官方宣布结束开源发布支持；商业支持是另一条安排，不能当成免费的社区维护。新课程优先验证 4.1.x，而不是只因旧教程多就默认选择 3.5.x。教学概念仍保持 IoC/DI、MVC、MyBatis 与事务，不增加一门“Boot 3 升级 Boot 4”课 [S12][S13]。

## 3. 目标重写为可观察的学习成果

完成课程后，每名学生应能够：

1. 在 JDK 21 上运行小程序，说明哪些语法源自 Java 8、哪些是后续加入的。
2. 独立修改发布、搜索、状态更新中的一条业务规则，并验证正常和异常情况。
3. 用 Git 提交和比较自己的改动；参与至少一次真实同伴审查。
4. 用参数化 SQL 完成数据读写，解释资源关闭和两次数据库修改的事务边界。
5. 说明一次 HTTP 请求如何经过 Controller → Service → Mapper/Repository → 数据库，再返回 JSON。
6. 用构造器注入组织对象，解释“原先手工 new 的依赖现在由谁提供”。
7. 对 AI 输出提出验证方案，发现并纠正至少一处不合适的建议；没有发现则如实记录，不能编造。
8. 在答辩现场不依赖 AI 完成一项小修改，并说清它可能影响的层和测试。

## 4. 建议坚持的范围边界

### 必做

- 商品发布、列表、名称搜索、详情、编辑/下架。
- 数据库持久化、参数校验、统一错误响应、必要的自动化测试。
- 第 5 周 JDBC 与第 10 周 Spring 事务各验证一次“同时成功/失败回滚”。
- 为事务采用简单案例：标记商品已售 + 插入成交记录；每件商品只能成交一次。
- 全部身份用虚构昵称；这只是本地业务流程演示，不是认证后的真实交易系统。

### 可选

- 分页以外的排序、单页展示、简短虚拟线程实验、动态代理演示、单一日志 AOP 切面。
- AOP 不挡结业；教师可演示后要求学生解释用途，而不要求人人独立编写。

### 不纳入本轮

- 真实支付、复杂登录/JWT/Spring Security、商品图片上传与审核、聊天室。
- Vue/React 前端、微服务、缓存、消息队列、容器编排、公网生产部署。
- 自制完整 IoC/ORM/MVC 框架、Java 21 预览特性作为项目依赖。

## 5. 原安排也可以保留的条件

若您特别看重底层机制，且学生已熟悉集合、异常和 SQL，可保留第 9 周迷你框架、第 10 周进入 Boot 的原节奏。但应缩小最终项目的要求，不能同时要求完整框架、全面 Boot 迁移、AOP、鉴权和部署。

本讨论稿默认选择：原生阶段服务于理解，最终重点放在能独立修改和验证 Spring Boot 分层项目。

## 6. 需与老师确认的三个问题

1. 学生目前是否已学完类/接口、集合、异常，以及 Lambda/Stream？能否独立写一个含输入和集合的小程序？
2. 每人每周能稳定投入多少课外时间？其中教师指导能安排几次、多长？
3. 最终更看重原生到框架的原理理解，还是一个较完整、能答辩的 Spring Boot 作品？

以上未确认前，课时、难度和具体框架补丁版本均为暂定。
