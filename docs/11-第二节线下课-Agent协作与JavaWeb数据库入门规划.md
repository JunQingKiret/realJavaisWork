- `docs/07-AgentAPI项目驱动学习方案.md`：103 智能仓管项目方向。

实际笔记已涉及变量、输入输出、比较、分支循环、方法调用、List 与物品搜索。不能据此认定全员已经掌握面向对象、异常、Maven、SQL、HTTP 和 Spring Boot。

本次建议把第二课定位为：

**围绕 103 仓库搜索功能，学会使用 Agent 澄清需求、辅助修改和验证，并看懂程序走向 Web 与数据库所需要的知识。**

一条任务主线：

原有控制台搜索 → 用户提出新需求 → 分析范围与验收 → 让 Agent 提供局部帮助 → 修改 Java → 验证行为 → 认识 Web 请求与数据库查询。

## 二、补充后的知识清单

“动手”表示本节有学生个人产出；“认识”表示能解释用途；“后续”表示另设练习，不计为本节已掌握。

| 模块 | 补充内容 | 本节深度 | 对应课堂问题 |
|---|---|---|---|
| AI 与 Agent | 模型、聊天界面、Agent、工具的关系 | 认识 | 会回答问题，是否等于已经执行了操作？ |
| 使用形态 | 对话式助手、通用任务 Agent、编码 Agent | 认识 | 解释代码、整理资料、修改工程分别怎样使用？ |
| Agent 执行过程 | 目标、上下文、计划、工具调用、观察结果、调整、停止 | 看一次演示 | 如何知道它真的查了文件、运行了程序？ |
| Prompt | 目标、背景、输入材料、约束、输出格式、验收条件 | 动手 | 怎样把一句模糊要求改成可执行任务？ |
| 上下文 | 当前代码、文件位置、错误原文、已尝试操作、运行环境 | 动手 | Agent 缺少什么信息时容易猜错？ |
| 结果核验 | 查看改动、实际运行、预期与实际对照 | 动手 | 页面或回答看着正确，功能是否真的正确？ |
| 项目需求 | 用户、痛点、场景、业务规则、功能和非功能要求 | 动手 | 谁在什么情况下使用？失败时怎么办？ |
| 项目评估 | 最小版本、优先级、任务拆分、依赖、工作量与不确定性 | 填简表 | 做搜索和做借还系统的范围差在哪里？ |
| Java 衔接 | 参数与返回值、String、遍历、局部修改 | 动手 | 输入的关键词经过了哪些方法？ |
| 对象建模 | Item 的字段；一个对象与 List<Item> 的关系 | 认识、后续练习 | 名称、位置、数量怎样描述同一件物品？ |
| JavaWeb | 浏览器与服务器、URL、端口、HTTP 请求与响应、JSON | 演示认识 | 在浏览器输入关键词后，谁真正完成查询？ |
| 工程基础 | JDK、Maven、依赖、配置、启动与错误日志 | 只认识入口 | 为什么拿到工程后不能只运行任意一个文件？ |
| MySQL | 数据库、表、行、列、主键、SELECT 与 WHERE | 演示；加长课动手 | 怎样存储并查出仓库物品？ |
| Java 连接数据库 | JDBC、连接参数、参数化查询、结果映射 | 后续 | Java 怎样把查询结果变成物品对象？ |
| 团队交付 | 分工、联调、验收、Git 改动记录与回退 | 认识、后续练习 | 如何说明自己完成了什么，怎样撤回错误修改？ |

### Agent 分类的讲法

“对话式、通用型、编码型”适合当作课堂上的使用场景分类，但它们会重叠，不是严格互斥的技术分类。聊天是交互形式；是否具有 Agent 特征，还要看系统能否围绕目标调用工具、观察结果并继续行动。

| 教学分类 | 本课示例任务 | 学生检查什么 |
|---|---|---|
| 对话式助手 | 解释为什么空关键字不应该被当作正常搜索 | 解释是否符合当前代码与需求 |
| 通用任务 Agent | 把仓库管理访谈整理成需求卡 | 是否虚构了用户要求或未查证的事实 |
| 编码 Agent | 阅读搜索方法，提出并完成一处局部修改 | 文件改动、编译运行、实际测试结果 |

再区分两种身份：本节使用的编码 Agent 是开发助手；未来仓库应用内面向用户的查询 Agent 是产品功能。使用前者不意味着必须现在接入后者。

## 三、用一项需求串起企业项目环节

老师扮演仓库管理员，提出原始要求：

> 我想做一个仓库管理系统，能找东西，最好还能智能一点。

学生先追问，不立即让 Agent 生成整个系统：

1. 谁会使用？普通查询者和管理员是否有不同权限？
2. 最常见的问题是找物品、查位置，还是登记借还？
3. 搜索按名称、编号还是分类？支持部分匹配吗？
4. 输入空白、找不到、多条结果时分别怎样处理？
5. 物品数据由谁提供和维护？
6. 第一版必须交付什么，哪些内容可以推迟？
7. 用什么具体输入和结果判断功能完成？

### 课堂需求卡示例

- 用户：需要查询物品的同学。
- 场景：知道部分名称，希望确认仓库是否有对应物品。
- 本节最小版本：复用现有物品列表，按名称搜索并给出明确反馈。
- 本节 Java 修改：搜索前去除关键词首尾空白，或补一个现有代码未满足的边界处理。教师课前检查实际代码后只选其中一项。
- 下一阶段 Web 演示：浏览器传入关键词，服务端返回查询结果。
- 下一阶段数据扩展：增加物品编号、位置与数量，不把新增字段伪称为第一课已实现内容。
- 暂不纳入本节开发：登录、借还审批、库存调整、统计报表、自然语言工具调用。
- 核心验收：正常关键词匹配；空白输入提示；无结果明确反馈；原有菜单与退出不受影响。

### 企业流程的课堂简化版

以下是教学用流程，不把它说成所有企业都固定遵循的唯一过程；实际开发会反复确认和调整。

| 环节 | 学生要回答的问题 | 最小产出 |
|---|---|---|
| 需求分析 | 为什么做、给谁用、什么场景、怎样算完成？ | 一页需求卡 |
| 范围和可行性评估 | 时间、人员、数据、技术与环境是否支持？ | 必做/后做列表与风险备注 |
| 方案设计 | 页面、接口、业务逻辑、数据分别负责什么？ | 一张结构草图与样例数据 |
| 任务拆分与排期 | 有哪些步骤、先后依赖、谁负责、如何估算？ | 小任务列表 |
| 开发与协作 | 一次改什么，怎样记录和检查？ | 一处可解释的代码改动 |
| 测试与联调 | 各部分单独与连在一起是否符合预期？ | 正常、异常、边界记录 |
| 验收与交付 | 使用者能否完成目标，如何启动和使用？ | 演示与简短使用说明 |
| 反馈与维护 | 发现缺陷或需求变化时怎么办？ | 问题清单与下一版本范围 |

评估示例：搜索功能可拆成需求确认、输入处理、查询逻辑、结果展示、测试；Web 化另外增加接口与页面联调；数据库化另外增加表设计、种子数据、连接和故障排查。让学生先区分“已经会”“需要查资料”“环境尚未验证”，再估算，不把 Agent 输出的小时数当承诺。

## 四、Prompt 教学：同一个任务，逐步补全信息

### 简单版本

> 帮我改进仓库搜索功能。

让学生指出缺失项：现有代码、改进目标、允许修改范围、输入输出规则、验收方法。

### 需求分析版本

```text
我正在把一个 Java 控制台仓库练习逐步扩展成 Web 应用。
现有功能是查看物品和按名称搜索，学生刚学过分支、循环、List 与方法。
目标用户是查询仓库物品的同学。
请先列出最多 5 个必须澄清的问题，再给出一个最小版本的需求卡。
区分“已知事实”“你的假设”“待我确认”。
输出用户、场景、功能范围、暂不做项和 4 条可执行验收标准。
这一轮不要生成代码。
```

### 局部开发版本

```text
任务：完善当前 Java 程序的搜索输入处理。
背景：这是 103 仓库控制台练习，保留现有菜单、数据和退出功能。
材料：我会提供当前完整搜索方法及其调用位置。
要求：去掉关键词首尾空白；处理后为空时给出明确提示。
如果现有代码已经满足要求，指出位置，不要为了产生改动而重写。
约束：使用我们学过的 Java 基础语法，不增加第三方依赖。
步骤：先解释输入经过哪些代码，再提出最小修改；实施后展示改动。
验收：正常名称、带首尾空白的名称、纯空白、无匹配结果。
输出：修改说明与真实运行结果；没有运行的项目请标注未验证。
```

### 错误反馈版本

```text
目标：……
输入：……
预期：……
实际：……
错误原文和相关代码：……
已尝试：……
请先定位原因，再提出局部修改，并说明如何复现和验证。
```

教师评价 Prompt 看“任务是否清楚、信息是否足够、约束是否可执行、结果是否可验收”，不按长度或角色扮演词汇打分。

## 五、JavaSE 怎样过渡到 JavaWeb 和 MySQL

### 1. 先复用学生认识的搜索功能

控制台版本：输入关键词 → Java 搜索方法 → 遍历 List → 控制台显示结果。

拟演示的 Web 版本：浏览器输入 → HTTP 请求 → Java 接收参数并查询 → JSON 响应 → 页面显示。

拟演示的数据库版本：Java 查询逻辑 → 数据访问代码 → MySQL → 查询结果 → Java → HTTP 响应。

这里的 Web 方案由服务端访问数据库，浏览器不持有数据库账号。List、JSON、数据库表可以表达相关业务数据，但三者分别是程序内的数据结构、交换格式和数据库中的数据组织，不能当作同一个东西。

### 2. 把“为什么要学”放在知识名词前面

| 需求变化 | 引出的知识 | 本节边界 |
|---|---|---|
| 物品除了名字，还有位置和数量 | 类、对象、字段、List<Item> | 看一件物品的模型，后续手写 |
| 希望通过浏览器使用 | 浏览器/服务器、HTTP、URL、端口 | 看一次请求往返 |
| 页面需要可解析的结果 | JSON、字段与数组 | 对照响应看懂含义 |
| 程序重启后还要保留新增数据 | 持久化与数据库 | 比较内存临时数据和保存到数据库的数据 |
| 想按条件筛选物品 | SELECT、WHERE | 看懂并修改一个筛选条件 |
| Java 要读取 MySQL 数据 | JDBC、参数化查询、结果映射 | 下一阶段单独实践 |

### 3. JavaWeb 演示脚本（待备课实现）

建议教师准备一个已启动、能运行的最小 Spring Boot 示例，以减少课堂配置时间；本节不要求学生从空工程搭建。

1. 浏览器提交一个关键词。
2. 查看请求路径、查询参数、响应状态与 JSON。
3. 在 Java 方法中定位接收到的关键词。
4. 对照原来控制台搜索，指出相同的业务规则。
5. 故意输入空白关键词，比较正常与错误反馈。

拟定接口合同：`GET /api/items?keyword=键盘`。

- 正常匹配：200，返回物品数组。
- 无匹配：200，返回空数组，页面显示“未找到”。
- 关键词缺失或去除空白后为空：400，返回明确提示。
- 教师备课时验证上述合同，不以截图代替实际联调。

本节对 Controller 只解释为接收请求的入口；Service 和数据访问层按职责展示。Servlet、容器、请求生命周期后续补概念；若学校要求 JSP/Servlet 实操，另设对应训练，不混入这 90 分钟。

### 4. MySQL 演示脚本（待备课实现）

使用独立教学库和虚构数据。拟定物品表的最小字段为 id、name、location、quantity；id 用于唯一标识物品。

```sql
SELECT id, name, location, quantity
FROM item
WHERE name LIKE '%键盘%';
```

学生观察：从哪张表查、取哪些列、按什么条件筛选。加长课可在 SQL 客户端修改条件并运行。

这是在 SQL 客户端演示的固定查询。后续接入 Java 时使用参数化查询绑定输入，不示范将用户输入直接拼进 SQL。

本节不引入 JOIN、事务隔离、索引优化与 ORM 配置。数据库安装和连接故障提前排查；没完成安装的学生先使用教师演示与结果样例，不把安装耗时挤进主课。

## 六、90 分钟课堂安排

| 时间 | 教师活动 | 学生活动与产出 |
|---|---|---|
| 0–8 分钟 | 运行上一课搜索程序，检查基础衔接 | 指出输入、搜索方法、遍历和输出位置 |
| 8–18 分钟 | 用同一个仓库任务说明三种 AI 使用形态，展示一次工具结果 | 判断哪些是回答、计划、真实执行证据 |
| 18–33 分钟 | 扮演需求提出者，带学生澄清范围与评估 | 完成一张简版需求卡 |
| 33–45 分钟 | 对比模糊 Prompt 与明确任务 | 每人改写一条提示词，指出验收条件 |
| 45–60 分钟 | 引导 Agent 辅助一次 Java 局部修改 | 查看改动、运行、解释本人完成的修改 |
| 60–72 分钟 | 展示浏览器请求 Java、返回 JSON | 追踪关键词的输入与返回结果 |
| 72–82 分钟 | 演示物品表和一条 SELECT 查询 | 指出表、字段、条件；写出拟修改条件 |
| 82–90 分钟 | 验收、离场票、布置分层练习 | 提交需求卡、提示词、改动与至少 3 项测试记录 |

90 分钟的合格成果：一次完整的“明确任务—请求帮助—局部修改—验证”，外加 Web 和数据库的初步认识。不能宣称学生已经完成 Spring Boot + MySQL 独立开发。

### 超时与基础不足时的取舍

- 超过三分之一学生无法运行旧程序：Java 环节改为运行和定位练习，Web/数据库合并成短演示，安排课后补练。
- 60 分钟时 Java 修改仍未收尾：优先保证运行和验收；Web 与 SQL 只各展示一个例子，不追加编码。
- Agent 网络不可用：使用课前保存的任务、改动与真实运行记录，并明确标注为回放。
- 所有人都必须解释一个行为或完成一次操作；结对时轮换，避免一人完成整组任务。

### 如果实际课时为 150 分钟

在上述 90 分钟基础上增加：

- 10 分钟休息；
- 20 分钟个人接口体验：访问正常与空白关键词请求，记录状态和响应；
- 20 分钟个人 SQL 练习：运行查询、修改条件、核对结果；
- 10 分钟小组演示与个人解释。

这版仍以教师提供的已验证工程为前提；从零建工程和完整数据库接入留到后续课。

## 七、课前准备与课后验收

### 学生课前准备

1. 带上第一课可运行代码。
2. 能找到输入、分支、循环、搜索方法和列表遍历。
3. 带一个自己遇到的问题，记录输入、预期、实际或错误原文。
4. 打开本课使用的 Agent 工具并完成一次基本交互；不要求本节申请模型 API Key。

### 教师备课材料（本规划未生成这些工程）

- 旧程序正常版与一个局部待改版本。
- 一页需求卡模板和一组模糊/明确 Prompt 对照。
- 已验证的最小 Web 工程、启动说明、接口合同与响应样例。
- 教学数据库、建表与种子数据脚本、一条可运行查询。
- 若完整数据库链路未接通，明确标注演示是分段的，不称为端到端完成。
- Agent 失败时可使用的回放材料。

### 个人验收

| 检查项 | 可接受证据 |
|---|---|
| 需求理解 | 说出用户、一个必做项、一个暂不做项与一条验收条件 |
| Prompt | 提供背景、材料、约束和可判断的完成标准 |
| Java 贡献 | 指出本人修改的位置，解释输入与输出受到什么影响 |
| 行为验证 | 记录正常、空白、无结果三个场景的预期与实际 |
| Web 认识 | 指出浏览器发出的请求和服务端返回的结果 |
| 数据库认识 | 看懂查询中的表、列和条件 |

课后作业继续同一案例：基础组补齐运行与边界处理；标准组完善需求卡并解释 Web 数据流；进阶组在已有环境中完成两条条件查询。尚未具备环境的学生不被要求独立配置整套系统。

## 八、备课时顺手修正第一课的语法表述

课堂笔记有些示意写法不适合直接交给学生当作可运行 Java 代码。建议在复习页统一：

- 字符串类型写 `String`。
- 数组长度用 `.length`，String 长度用 `.length()`，List 元素个数用 `.size()`。
- Java 的循环条件使用 boolean 表达式，如 `while (running)` 或 `while (true)`。
- 普通 `void main` 方法退出可用 `return;`，不要直接写 `return 0;`。
- 展示代码时标清“伪代码”“待补全代码”和“可运行代码”。

这些是备课修正项，本次不修改第一课原始记录。

## 九、后续课程路线：按能力推进，课次可拆分

| 建议阶段 | 核心问题 | 主要知识 | 完成标志 |
|---|---|---|---|
| 第 2 课：本节 | 怎样用 Agent 协作完成一个明确任务？ | 需求、Prompt、局部修改与验证，Web/SQL 概览 | 有本人完成和验证的修改 |
| 第 3 课：对象与工程 | 怎样完整表示物品并组织代码？ | 类、对象、字段、构造方法、List<Item>、异常入门、Maven 基础 | 独立增加字段并完成列表查询 |
| 第 4 课：MySQL | 怎样长期保存并查询物品？ | 建库建表、主键与约束、基础 CRUD、简单条件 | 写出并验证几条 SQL |
| 第 5 课：Java 访问数据库 | 怎样用 Java 查询真实数据？ | JDBC、参数化查询、资源释放、结果映射、连接错误处理 | Java 查询结果与数据库一致 |
| 第 6 课：JavaWeb | 怎样让浏览器调用查询功能？ | HTTP、JSON、基础 Spring Boot 接口、输入校验 | 独立完成并验证一个查询接口 |
| 第 7 课：最小应用联调 | 怎样把页面、接口、数据连起来？ | 教师提供基础页面，学生联调、日志排错、验收与 Git 协作 | 从页面查询并展示数据库结果 |
| 第 8 阶段：仓库内的 Agent | 怎样让自然语言调用已可靠的查询能力？ | 工具参数、结果返回、失败处理、执行核验 | 自然语言查询可追溯到实际工具结果 |

第 3–7 阶段继续使用开发助手，但每阶段保留学生独立解释、修改和验证。每阶段可以拆成多次课，不承诺一节掌握整章。若原定第三课必须保留汇报与 Git，可先做一次成果展示，再进入对象与工程阶段。

## 十、技术核对资料

以下资料用于核对技术概念，不是要求学生全部课前阅读。课程节奏与范围是针对当前基础的教学建议。

- Anthropic：《Building effective agents》：区分预设工作流与模型动态选择工具和步骤的 Agent，说明环境反馈与验证的作用。
- Spring 官方：《Building a RESTful Web Service》：HTTP 请求到 Java Controller，再返回 JSON 的最小示例。
- MySQL 8.4 Reference Manual：Tutorial，数据库、表、数据录入与查询入门。
- MDN：《Overview of HTTP》：客户端、服务端、请求与响应。
- Oracle Java Tutorials：《Using Prepared Statements》：参数化查询与用户输入处理；该教程基于 JDK 8，参考其基础概念，不据此决定本课的依赖版本。

实际备课时继续使用已验证的 JDK 环境，并为教师工程固定和验证依赖版本。本规划没有作“最新版本”承诺，也没有进行工程构建测试。
