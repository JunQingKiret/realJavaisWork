# 第一周教学大纲：V0 独立启动与基础诊断

> 教师可执行讨论稿 v0.1｜尚未确定开课日期。D1–D7 表示开课后的相对日，不是已经排定的实际日期。

## 1. 本周定位

**不重新讲一遍 Java 入门；用一个独立小项目判断每个人的基础，再按需补课。**

每人完成一份“校园二手交易平台”控制台内存版，具备菜单、发布、列表、按名称搜索和退出。所有数据仅在本次运行中保留。重启后为空是本周的预期行为，正好为后续持久化留下问题。

本周不装数据库，不要求 Maven，不用 AI 生成业务代码，不把程序开发按成员分工。允许交流和结对排查，但每个人必须有自己的程序并能解释。

## 2. 周末可观察的学习目标

学生能够：

1. 说明学校 Java 8 项目与本次 JDK 21 项目的区别，并独立运行当前程序。
2. 追踪“读取输入 → 校验 → 存储 → 列表/搜索输出”的数据流。
3. 用方法拆开菜单、发布、列表、搜索；主循环不会因普通非法输入退出。
4. 用 Git 保存至少 4 次有意义的迭代，并解释其中一次改动差异。
5. 不依赖 AI 现场修改一个小规则，并用一个正常用例和一个边界用例验证。
6. 识别文本块是 Java 8 之后加入的特性；可选认识 var/箭头 switch，不要求全部使用新语法。

## 3. 范围与数据约定

### 最小菜单

- 1：发布商品。
- 2：查看全部商品。
- 3：按名称搜索。
- 0：退出。

### 统一数据模型

默认使用一个薄的普通 `Product` 类和 `ArrayList<Product>`。字段：

| 字段 | 约定 |
|---|---|
| id | 当前运行内唯一、递增的正整数；成功发布才分配 |
| name | 去除首尾空白后非空；建议不超过 30 个字符 |
| priceInCents | 使用 long 保存整数分；输入显示以元为单位 |
| description | 可以为空；只作为文字展示，不引入富文本 |

- 已学类和集合者自己写；尚未学到者由教师提供只含字段、构造器和读取方法的 Product，以及最小集合使用示例。
- 教师提供两个价格辅助方法的骨架/实现：金额字符串转整数分、整数分显示成两位小数。学生实现输入、调用和错误提示，不在本周深挖金额库。
- 价格规则：大于 0、不超过 99999.99 元；只接受普通十进制，最多两位小数。`18`、`18.5`、`18.50`有效；`abc`、`-1`、`0`、`18.555`、`1e3`无效。
- 教师辅助方法可在内部使用精确十进制处理；不采用 double/float 保存交易金额，不将复杂正则或金额解析作为本周独立考核项。
- Product 内存字段和后续数据库列采用一致的金额表示；第 2/5 周再解释理由与持久化映射。
- 第一周普通类可先使用，第 2 周再谈封装和职责；ArrayList 第一周会调用即可，第 3 周再系统比较集合。
- 不同时实现数组版和集合版，不要求学生用平行数组存名称、价格和描述。

### 输入行为

- 所有控制台输入优先统一读整行；读菜单后再解析，避免数字读取和整行读取混用带来的换行问题。
- 菜单输入不是合法选项时，提示后重新显示菜单，不打印堆栈作为用户提示。
- 发布字段非法时，提示并重新输入该字段；不保存半条商品，不分配成功编号。
- 列表为空时显示“暂无商品”；搜索没有匹配时显示“未找到商品”。
- 搜索关键字去除首尾空白；为空则提示并返回菜单；非空时匹配名称中的子串，英文忽略大小写。
- 输入辅助方法里的异常要有针对性地处理；不以一个包住整个 main 的 catch(Exception) 吞掉所有问题。

## 4. 课前教师准备

1. 确认学生学校课已学到什么；提示学生保留校内 Java 8 环境。
2. 准备一份可运行的 V0 演示，只演示结果，不把完整学生答案发下去。
3. 如无最终 V6 演示，使用 2–3 个 API 请求/响应示例说明最终目标，不占时间提前做完项目。
4. 准备必要的 Product 和价格辅助代码，标明“教师提供”；不要把脚手架计为学生原创。
5. 提前在教学机器验证终端、编译器和编辑器都使用本项目的 JDK 21。
6. 准备一个没有敏感信息的工作目录；编码统一 UTF-8。为中文输入/输出准备简短排查说明。
7. 准备任务卡和 12 项验收场景；确定两次指导和周末验收的时间。

### 第一周最小环境

JDK 21、VSCode Java 支持、Git。已有其他熟悉的 Java 编辑器可经老师允许继续使用，学习目标不绑定点击路径。

检查顺序：

- 终端 `java -version` 和 `javac -version` 显示 21。
- 编辑器当前拓展项目使用 JDK 21；保持学校项目仍按学校要求配置。
- 学生能运行一个最小程序；使用文本块的练习可验证语言级别并非仍设为 8。
- 本地 Git 能提交；远程仓库账号和推送可以后移，不挡本周完成。

不把 `mvn -version`、MySQL、Postman 和 AI Agent 安装作为本周门槛。

## 5. 第一次指导：75 分钟（D1）

| 时间 | 教师活动 | 学生活动与检查 |
|---|---|---|
| 0–5 分钟 | 演示 V0；介绍从内存到 Boot 的演进，明确本周边界 | 用自己的话说出本周 5 个功能；认识重启丢数据是预期 |
| 5–20 分钟 | 组织基础诊断，不计分：写一个循环菜单雏形，指出一个输入错误，口述方法/集合用途 | 独立尝试，不互抄；老师记录缺口而不是排名 |
| 20–35 分钟 | 检查 JDK/编译器/编辑器；说明双环境 | 每人运行最小程序；记录环境问题和解决方式 |
| 35–45 分钟 | 演示 Git 初始化、差异、暂存、提交 | 建本地仓库，提交最小可运行程序与忽略配置 |
| 45–65 分钟 | 按诊断补循环/分支/方法；菜单讲完才用文本块做 5 分钟对比 | 写菜单与退出路径；先允许传统 switch；现场运行两轮 |
| 65–75 分钟 | 明确任务卡 A 和求助方式；说明哪些辅助代码会提供 | 学生复述验收标准，记录最可能卡住的点 |

### 诊断后的分层

- **基础待补**：老师给菜单结构提示、最小 Product 和价格辅助代码；优先完成菜单与发布/列表。
- **基础正常**：自己写方法和 Product，价格辅助代码可共用。
- **基础较强**：不抢先学 Spring；补更多边界场景、说明设计取舍或帮助同伴定位问题，不代写。

诊断不通过不意味着退出项目；根据缺口调整下一周安排。

## 6. 第一次自主练习：60 分钟（D2，任务卡 A）

必做：

1. 完成显示菜单、读取选择、0 退出；1/2/3 可先只显示功能提示。
2. 输入 `abc`、空白、`9` 后仍能回到菜单。
3. 至少完成“初始化”和“菜单”两次有意义提交。
4. 填写一条三句话进度：做了什么、卡在哪、下一步。

提交证据：能运行的代码 + 两个输入场景的文字结果。不要求制作录屏。

若超时仍卡住，提交当前状态和最小错误，不继续盲试到深夜。卡住 20–30 分钟即可向教师/同伴提问。

## 7. 第二次指导：75 分钟（建议 D4）

| 时间 | 教师活动 | 学生活动与检查 |
|---|---|---|
| 0–10 分钟 | 复盘菜单和共性输入问题 | 每人展示菜单/退出；基础薄弱者优先排障 |
| 10–25 分钟 | 演示一条商品的数据流；解释 Product 与集合的最小使用 | 口述字段、记录存放位置、成功发布才分配 id |
| 25–45 分钟 | 指导发布/列表，提供价格辅助方法 | 每人发布并查看一条商品，老师确认保存的是有效数据 |
| 45–60 分钟 | 拆解名称搜索：去空白、非空、遍历、子串比较 | 写出搜索步骤；验证一个能找到、一个找不到的例子 |
| 60–70 分钟 | 演示阅读差异和功能提交；同伴口述审查 | 两两检查一个方法，不直接替对方写完 |
| 70–75 分钟 | 发布任务卡 B/C 和验收要求 | 每人确定剩余任务；可选任务不作为追赶条件 |

## 8. 第二、三次自主练习：各 60 分钟

### D5：任务卡 B——发布与列表

- 完成发布和列表；至少发布 3 个虚构商品。
- 非法名称/价格不能生成新商品。
- 列表包含 id、名称、两位小数金额、描述；空列表给出提示。
- 做一项有明确功能变化的提交。若发布和列表分两次完成，可分别提交。

### D6：任务卡 C——搜索、测试与说明

- 完成搜索，验证命中、多条命中、未命中、空关键字和英文大小写。
- 按验收表进行自测，修复最影响运行的问题。
- 写最小 README：本周环境、运行方式、已做功能、已知问题、教师提供的代码范围。
- 填 AI_LOG：若只查官方资料则记录资料；没使用 AI 就写“本周未使用 AI”，不为完成材料强行提问。
- 完成一项功能或修复提交，发送第二条三句话进度。

时间不够时先完成必做与失败记录，删除选做，不以“看起来功能多”换取基本路径失败。

## 9. 周末验收：全组 30 分钟（D7）

- 3–4 人每人约 5 分钟：1 分钟运行、2 分钟解释、2 分钟现场小改及验证。
- 剩余约 10–15 分钟汇总问题、回顾版本痛点、布置第 2 周重构方向。
- 详细输入场景在验收前由学生自测填写；现场抽查 2–3 项，不把 12 项全部重复演示。
- 现场修改不使用 AI；允许查自己的代码和简短 API 提示，不把打字速度当能力。
- 若改动当场未完成，说明思路并安排短补验收；不让其他成员替答。

### 现场小改题，选一项

1. 把“商品名称最长 30 个字符”改为 20，并验证 20 和 21 个字符。
2. 把搜索结果加上“共找到 N 件商品”，验证零件和多件。
3. 把名称搜索改为只从首部匹配，解释原先子串匹配与新规则的区别。
4. 增加退出确认，并验证确认与取消两条路径。

不要随机要求加入 JDBC、登录或未讲过的算法。

## 11. Git、文件与材料要求

### 学生项目建议目录

- `src/`：Main、Product 和必要辅助类；此时还不是 Maven 标准目录。
- `README.md`：运行说明和已知问题。
- `.gitignore`：不提交 class 文件、输出目录、系统垃圾文件和敏感配置。
- `AI_LOG.md`：未使用/使用情况。
- `week01-checklist.md`：可直接采用学生任务卡中的测试表。

第 4 周再迁到 Maven 的 `src/main/java`、`src/test/java`。不在第一周增加目录迁移练习。

建议忽略：`*.class`、`out/`、`bin/`、`target/`、`.idea/`、`*.iml`、`.DS_Store`、`Thumbs.db`。`.vscode/` 是否共享由老师决定：可移植设置可以留，含本机绝对路径/敏感信息的配置不提交；不一概忽略所有可共享配置。

### 提交要求

至少 4 次有真实意义的提交，例如：

1. `chore: 初始化项目`
2. `feat: 添加菜单与退出`
3. `feat: 完成商品发布与列表`
4. `feat: 完成名称搜索`

有修复则另加 `fix:` 提交。先讲 chore/feat/fix 即可，其他前缀以后按需引入。不允许一次写完后拆空提交凑数量。

### 最小材料

- 仓库或本地项目文件。
- README 中一段环境验证结果，以及一段运行说明；不必额外收集大量截图。
- 测试清单，记录通过/失败/未做，不留空假装都通过。
- AI_LOG 和一条真实问题解决记录。
- 现场口述或 3 分钟录屏二选一；优先现场，减少制作成本。

## 13. 常见卡点与教师处理

| 卡点 | 优先处理 |
|---|---|
| 终端 21，编辑器仍按 8 编译 | 检查当前项目运行/语言级别，不卸载学校 JDK |
| 读完数字后名称变成空串 | 统一按整行读取，再解析；解释换行残留 |
| 数字解析报错直接退出 | 对该输入边界捕获具体错误并提示，不吞所有异常 |
| 输入错误后列表出现不完整商品 | 所有字段校验完再创建并加入集合 |
| 把价格存为浮点数 | 使用教师提供的整数分辅助方法，本周不过度展开金额运算 |
| 搜索只返回一条 | 检查循环中是否过早 return/break；用两条命中验证 |
| Git 只有最后一次提交 | 检查任务卡分段是否太大；允许诚实说明，不补造历史 |
| 强学生替弱学生写完 | 改为“提出一个定位问题”；验收仍由本人独立完成 |

## 14. 第一周结束后的教师复盘

记录每人的四项状态：输入处理、方法拆分、类/集合使用、解释与修改。第 2 周据此决定：

- 多数人顺利：进入职责重构，比较普通类和 Record 数据载体。
- 一人明显薄弱：单独给一个 20–30 分钟补练，用本周预算替换其选做任务。
- 多数人未达到门槛：第 2 周先补输入/方法/集合，不急着堆新特性；相应减去后期选做。

给学生的收尾问题：“程序现在可以用，为什么重启就没有商品？如果以后同时有控制台和网页入口，业务规则应该放在哪里？”这为后续持久化与分层埋下问题，不要求本周给出框架答案。
