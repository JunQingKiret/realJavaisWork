# 第一节线上 Java 基础补齐课规划

> 教师执行讨论稿 v0.1｜2026-10-18  
> 暂按 10 名学生、腾讯会议、90 分钟设计。  
> 本稿只规划第一节基础课；第二节 WorkBuddy AI 协作和第三节汇报、Git 团队协作不在本节展开。

## 1. 本节课到底要补到什么程度

本节课不追求“讲完 Java 基础”，而是建立进入第二节 AI 协作前的最低能力基线：

> 学生能够独立打开一个小型 Java 项目，运行程序，找到需要修改的位置，读懂输入、分支、循环、方法和简单 List 遍历，完成一个小改动，并用正常、异常和边界输入证明改动有效。

如果没有这条基线，第二节使用 WorkBuddy 时，学生只能判断“页面有没有生成”，无法判断代码改了什么、是否正确，也容易把 Agent 生成代码直接当答案。

### 1.1 全员必须过关

| 能力 | 过关表现 |
|---|---|
| 文件与运行 | 能找到 `src`、入口类和 `main`，会运行、停止和再次运行 |
| 输出、变量与 String | 能修改提示文字，能声明、读取和使用字符串变量 |
| 输入与分支 | 能用字符串菜单处理 `1`、`2`、`0` 和未知输入 |
| 循环与退出 | 菜单能重复执行，输入 `0` 后正常退出，不出现死循环 |
| 方法阅读 | 能说清“传入什么、返回什么、在哪里调用”，并修改一条局部规则 |
| List 阅读 | 能读懂教师提供的 `List<String>` 和 `for-each` 遍历，不要求独立设计泛型 |
| 验证 | 会先写预期，再运行至少 3 类输入：正常、异常、边界 |
| 错误定位 | 能区分编译错误、运行结果不符合预期和环境无法启动 |

### 1.2 可以暂缓

- 独立设计 `Product`、`InventoryItem` 等业务类；
- 构造器、封装、继承、接口和完整面向对象设计；
- `ArrayList<Product>` 的增删改查；
- 异常体系、Maven、数据库、HTTP、Spring Boot；
- Stream、Lambda、Record 和其他 Java 21 新语法；
- WorkBuddy 的具体操作、提示词技巧和 Agent 工作流；
- Git 分支、合并、冲突、Pull Request 和团队仓库规则。

本节只允许在收尾时说明后续安排，不提前消耗第二、三节课的内容。

## 2. 第二节课前的硬门槛

学生满足以下四项，才算达到 WorkBuddy 协作的起步线：

1. 能独立运行教师项目，不由同伴代操作；
2. 能指出输入、分支、循环、方法调用和 List 遍历分别在哪里；
3. 能完成一个 3–8 行的局部修改，并说明为什么改这里；
4. 能执行至少 5 个给定场景，发现一项不符合预期时知道先保留错误信息。

未通过者不取消第二节课参与资格，但第二节只能先做观察员和验证员，并在课前或课后完成 20–30 分钟定向补练，不能直接让 WorkBuddy 代写未掌握的基础逻辑。

### 3.1 必备资料

| 资料 | 内容 | 使用时机 |
|---|---|---|
| 课前检查清单 | JDK、编辑器、项目路径、中文输入、腾讯会议共享屏幕 | 课前一天发送 |
| 8 页以内的教师演示稿 | 本节目标、运行链路、输入、分支、循环、方法、List、验证 | 课堂投屏 |
| 一页基础速查 | `println`、`Scanner.nextLine`、`trim`、`equals`、`while`、方法、for-each | 学生练习时查看 |
| 启动骨架 | 可运行，但保留 4 个明确 TODO，不提供完整答案 | 课堂主练习 |
| 教师完整答案 | 含正确逻辑、测试输入和常见错误版本 | 仅教师保存 |
| 预期输出样例 | 让学生先对照行为，不通过猜测判断正确 | 综合练习与验收 |
| 常见错误卡 | `==` 比字符串、循环条件写反、忘记退出、变量作用域、括号缺失 | 卡点统一讲解 |
| 学生状态表 | 每人记录运行、分支、循环、方法、List、验证六项状态 | 课堂观察与补练 |

### 3.2 演示稿建议页序

1. 今天的唯一目标：能看、能改、能跑、能验证；
2. 一个 Java 程序从文件到运行结果的最短链路；
3. 输入进入变量；
4. 分支决定执行哪一条路径；
5. 循环让程序继续工作，退出条件负责停止；
6. 方法是有名字、输入和结果的一段任务；
7. List 保存多项数据，遍历逐项检查；
8. 修改完成不等于正确，必须用场景验证。

不要做 Java 历史、JDK 版本特性、完整 OOP 或 IDE 功能介绍。

## 4. 90 分钟线上课堂流程

| 时间 | 环节 | 教师动作 | 学生产出 |
|---|---|---|---|
| 0–6 分钟 | 入会与运行检查 | 聊天区收集 `1 已运行 / 2 有问题 / 3 未打开`；只处理共性问题 | 每人成功看到起始输出，或进入教师共享环境 |
| 6–12 分钟 | 结果演示 | 演示完整小程序：列表、搜索、错误输入、退出；不展示答案代码 | 说出程序至少需要哪几种行为 |
| 12–24 分钟 | 六题微诊断 | 逐题投票或聊天提交，不公布排名 | 形成个人红黄绿状态 |
| 24–39 分钟 | 输入与分支 | 带做 TODO 1：读取字符串菜单并完成 `1/2/0` 分支 | 单次选择能得到正确结果 |
| 39–51 分钟 | 循环与退出 | 用“一次就结束”的故障版引出 `while` 和退出变量 | 菜单可重复，`0` 正常结束 |
| 51–63 分钟 | 方法与 List 阅读 | 只讲参数、返回值、调用点；提供 List 创建代码，逐项追踪 for-each | 能口述搜索方法的数据流 |
| 63–79 分钟 | 独立综合练习 | 学生完成 TODO 2–4；教师只回答最小问题 | 每人得到可运行的个人版本 |
| 79–87 分钟 | 五场景验证 | 要求先写预期，再运行；抽两人共享屏幕 | 自测表有实际结果，不只写“通过” |
| 87–90 分钟 | 离场票 | 收集“已会、卡点、补练项”；说明第二节准入线 | 教师得到个人基础状态 |

线上课堂每 10–12 分钟要求一次可见动作：聊天回答、投票、运行结果或共享屏幕。不要连续讲解超过 12 分钟。

## 5. 六题微诊断

诊断不计分，用于决定学生做基础版还是解锁版。每题控制在 1–2 分钟。

### 题 1：变量与输出

```java
String name = "螺丝刀";
System.out.println("物品：" + name);
```

问题：输出是什么？如果要改成“物品：键盘”，最少改哪里？

观察点：能否识别字符串变量及其使用位置。

### 题 2：字符串比较

```java
if (choice == "1") {
    System.out.println("查看物品");
}
```

问题：这段代码可能出现什么问题？本课统一使用什么写法？

教师答案要点：字符串内容比较使用 `"1".equals(choice)`；本节不展开对象相等性理论。

### 题 3：分支覆盖

要求学生说出菜单输入 `1`、`2`、`0`、`9` 分别应走哪条路径。重点检查是否遗漏未知选项。

### 题 4：循环退出

```java
boolean running = true;
while (running) {
    // 菜单逻辑
}
```

问题：输入 `0` 时至少需要改变什么，程序才会停止？

### 题 5：方法阅读

```java
static boolean containsKeyword(String item, String keyword) {
    return item.toLowerCase().contains(keyword.toLowerCase());
}
```

问题：这个方法接收什么，返回什么？返回 `true` 代表什么？

### 题 6：验证场景

搜索功能已经能找到“螺丝刀”。还至少应该测试哪三种输入？

教师答案要点：部分关键字、找不到、空字符串；有余力可补大小写和前后空格。

### 诊断分层

- **红色 0–2 题清楚**：只完成菜单、分支、循环和退出；搜索方法由教师提供，学生负责运行验证。
- **黄色 3–4 题清楚**：完成全员任务，并补全搜索方法中的条件判断。
- **绿色 5–6 题清楚**：完成解锁题，增加结果计数或低库存筛选。

分层只改变脚手架，不公开排名，不允许绿色学生代替红色学生操作。

## 6. 课堂练习题

### 练习 A：菜单单次分支，全员必做

要求：

- 输入 `1`，显示所有固定物品；
- 输入 `2`，先只显示“准备搜索”；
- 输入 `0`，显示“已退出”；
- 其他输入显示“无效选项：请输入 1、2 或 0”。

约束：菜单先按字符串处理，不做整数解析，不引入异常捕获。

### 练习 B：让程序继续工作，全员必做

教师先提供“一次选择后程序结束”的版本，学生补充循环。

验收输入：

```text
1 → 9 → 1 → 0
```

预期：前 3 次操作后菜单都会再次出现，最后一次正常退出。

### 练习 C：读懂方法和 List，全员必做

教师提供以下数据创建代码，不要求学生默写：

```java
List<String> items = Arrays.asList(
        "螺丝刀",
        "Keyboard",
        "打印纸",
        "安全帽"
);
```

学生要完成：

1. 指出 List 中有几项；
2. 指出 for-each 每轮的 `item` 分别是什么；
3. 在搜索方法中补全“包含关键字时输出物品”的判断；
4. 解释为什么搜索 `key` 应找到 `Keyboard`。

### 练习 D：独立局部修改，全员必做

四选一，每人独立完成一项：

- 无效输入时同时回显用户输入；
- 搜索关键字为空时给出提示并返回菜单；
- 退出时增加一行总结信息；
- 列表输出时增加从 1 开始的序号。

必须说明：改动位置、预期结果、实际使用的验证输入。

### 练习 E：解锁题，不作为全员门槛

- 搜索完成后显示“共找到 N 项”；
- 搜索前对输入执行 `trim`；
- 新增一个固定的库存数量 List，筛选数量小于 5 的项；
- 把列表显示或搜索逻辑拆成独立方法，并在 `main` 中调用。

不建议第一节课让学生自行设计 `InventoryItem` 类，否则会把有限时间从行为理解转移到构造器和字段语法。

## 7. 综合题：Warehouse Basics V0

### 7.1 学生收到的功能要求

```text
===== 103 仓库基础练习 =====
1. 查看所有物品
2. 按名称搜索
0. 退出
请选择：
```

全员版本必须满足：

1. 菜单可以重复显示；
2. `1` 显示教师提供的固定物品；
3. `2` 读取关键字并显示所有包含该关键字的物品；
4. 空关键字给出提示，不执行“全部匹配”；
5. 没有结果时显示“未找到”；
6. 未知选项提示后继续；
7. `0` 正常退出。

### 7.2 启动骨架中的四个 TODO

```text
TODO 1：补全菜单分支
TODO 2：让菜单重复运行并能退出
TODO 3：补全搜索方法中的匹配判断
TODO 4：区分“未找到”和“找到至少一项”
```

红色档学生可由教师提供 TODO 3 的主体，但仍须解释方法输入、输出和至少三个验证场景。黄色和绿色档学生自行补全。

## 8. 统一自测题

| 编号 | 操作 | 预期行为 |
|---|---|---|
| T01 | 启动 | 显示标题和 1/2/0 菜单 |
| T02 | 输入 `1` | 显示 4 项固定物品，之后回到菜单 |
| T03 | 输入 `2`，搜索 `螺丝` | 找到“螺丝刀”，之后回到菜单 |
| T04 | 输入 `2`，搜索 `key` | 找到 `Keyboard`，验证大小写处理 |
| T05 | 输入 `2`，搜索不存在内容 | 显示“未找到”，之后回到菜单 |
| T06 | 输入 `2`，关键字为空或全空格 | 提示关键字不能为空，不显示全部物品 |
| T07 | 输入 `9` 或 `abc` | 提示无效选项，程序继续 |
| T08 | 连续执行 `1 → 2 → 9 → 0` | 前三步回到菜单，最后正常退出 |

课堂至少完成 T01、T03、T06、T07、T08。其余可作为课后 15 分钟自测。

## 9. 在线教学的组织规则

### 9.1 腾讯会议状态码

- `1`：已完成，可以继续；
- `2`：有问题，但还能跟上；
- `3`：阻塞，需要教师查看；
- `C`：代码编译错误；
- `R`：能运行，但结果不对；
- `E`：环境或项目无法启动。

教师看到同一问题达到 3 人时，暂停个人答疑，回主会场统一讲解 3 分钟。

### 9.2 求助格式

```text
我正在完成：
我输入了：
我预期看到：
实际看到：
错误信息或截图：
我已经检查过：
```

第一节不允许只发“不会”“报错了”或只截一张没有上下文的红字图片。

## 10. 过关验收

每名学生 2–3 分钟，人数较多时可在课后分两批完成，不占用主课全部时间。

1. 运行 `2 → 空关键字 → 2 → 有效关键字 → 0`；
2. 指出读取输入、分支、循环、搜索方法和 List 遍历的位置；
3. 完成一个现场小改，例如修改错误提示或增加一个固定物品；
4. 说明用什么输入验证改动没有破坏退出和搜索。

### 10.1 判定规则

| 项目 | 通过条件 |
|---|---|
| 运行 | 本人能启动、停止和再次运行 |
| 基础控制流 | 分支、循环、退出行为正确 |
| 方法与 List | 能解释调用关系和逐项遍历，不要求背定义 |
| 修改 | 能独立完成一项局部改动 |
| 验证 | 至少 5 个场景有真实结果，包含异常或边界输入 |

只有最终输出截图、无法解释代码，或所有修改均由同伴完成，不算通过。

## 11. 课后补练与教师记录

课后不再布置一个新项目，只补本节未通过的能力。

| 未通过项 | 20–30 分钟补练 |
|---|---|
| 运行与文件 | 重新打开项目，修改一行提示，运行并截图完整路径与输出 |
| 分支 | 增加一个菜单选项，并验证已知与未知选项 |
| 循环退出 | 修复“一次就结束”或“无法退出”的故障版本 |
| 方法 | 修改方法参数或返回提示，指出调用点 |
| List | 增加一项数据，验证列表和搜索都能看到 |
| 验证 | 为已有功能补正常、异常、边界三类输入 |

教师课后形成一张基础矩阵：

| 学生 | 运行 | 输入/分支 | 循环/退出 | 方法 | List | 验证 | 第二节角色建议 |
|---|---|---|---|---|---|---|---|
| A | 通过/补练 |  |  |  |  |  | 驾驶员/观察员/验证员 |

第二节分组时，不把基础最弱的学生长期固定成记录员；可以先做验证员，但后续必须轮换到实际操作。

## 12. 第一节课的停止条件

达到以下状态就停止增加内容：

- 全班多数人能运行综合题；
- 每人完成至少一项独立修改；
- 学生知道如何用输入验证，而不是只看代码；
- 教师已经识别需要补练的学生和具体能力项。

即使提前完成，也不在第一节加入 WorkBuddy 任务、Git 分支协作、Maven、业务类设计或 Java 21 特性。多出的时间优先用于现场小改和错误排查。

## 13. 本节课最终产出

教师应拿到：

1. 每名学生的 `WarehouseBasics.java` 个人版本；
2. 至少 5 个场景的自测记录；
3. 一项本人完成的局部改动说明；
4. 一张全班基础能力矩阵；
5. 第二节课的角色与补练安排依据。

学生应带走的不是一份完整答案，而是一套最小工作方法：

> 先看目标和输入，再定位代码；一次只改一小处；运行正常、异常和边界场景；确认结果后再进入下一项任务。
