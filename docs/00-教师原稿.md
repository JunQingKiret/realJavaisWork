# Java 21 + Spring Boot 项目驱动教学方案书

> 原稿存档：由教师于本次对话提供。仅增加本存档说明，正文保留原稿；优化建议另见讨论稿。

## 一、任务目标

1. 掌握 Java 21 基础语法与面向对象核心，能独立编写控制台程序。
2. 理解工程化工具 Maven、Git，能用 VSCode 可视化 Git 管理代码迭代。
3. 掌握 JDBC、SQL、HTTP/JSON，能开发数据持久化与 Web API。
4. 理解反射、注解，能实现迷你 MVC 框架，自然过渡到 Spring Boot。
5. 掌握 Spring Boot 3.2+、IoC/DI、AOP、Spring MVC、MyBatis，完成项目迁移。
6. 分阶段引入 AI 协作，培养精准 Prompt 与批判性评估 AI 输出的能力。
7. 通过“校园二手交易平台”项目从 V0 到 V6 的迭代，体验从原生 Java 到 Spring Boot 的完整演进。

## 二、实训环境

- **硬件**：可上网的 Windows/macOS 电脑，内存 8GB 及以上。
- **软件**：Java 21 JDK、VSCode、Maven、MySQL、Postman、Git、AI Agent（如 Claude Code、Cursor、通义灵码等，V2 后使用）。
- **代码仓库**：Gitee 或 GitHub。
- **浏览器**：Edge/Chrome。

## 三、实训原理

本方案以**项目驱动、迭代演进**为主线，用一个贯穿项目“校园二手交易平台”承载全部知识点。每个版本（V0～V6）解决上一版的痛点，并逼出下一批技术：

| 版本 | 形态 | 核心技术 | 解决的问题 |
|---|---|---|---|
| V0 | 控制台内存版 | Java 基础语法、方法、数组、String、Scanner | 从零构建可运行程序 |
| V1 | OOP 重构版 | 类、对象、封装、接口、多态、Record | 代码可维护、可扩展 |
| V2 | 集合异常版 | 集合、泛型、异常、增强 switch | 数据管理更灵活、错误统一 |
| V3 | Maven+JDBC | Maven、SQL、JDBC、DAO、事务 | 数据持久化、工程化 |
| V4 | HTTP/JSON API | HTTP、REST、JSON、Jackson、虚拟线程 | 多客户端访问、前后端分离 |
| V5 | 反射注解迷你框架 | 反射、注解、代理 | 减少重复路由代码 |
| V6 | Spring Boot 迁移 | IoC/DI、AOP、Spring MVC、MyBatis、自动配置 | 企业级开发效率 |

同时，Git 采用 VSCode 可视化教学，AI 协作分阶段开放：V0-V1 禁用写代码，V2-V3 Coding Twice，V4-V5 Ask/Code/Review，V6 Agent 协作。全程记录 `AI_LOG.md`。

### 第一周详细步骤（V0 启动）

**1. 项目启动与需求拆解（线下 1）**
- 演示最终 V6 效果，明确 12 周目标。
- 拆解 V0 功能：菜单、发布商品、查看列表、按名称搜索、退出。
- 环境确认：`java -version` 为 21，VSCode 安装 Java 扩展，`mvn -version` 正常。

**2. Git 初始化与首次提交（线下 1）**
- VSCode 源代码管理 → 初始化仓库。
- 创建 `.gitignore`：`target/`、`.idea/`、`*.iml`、`.vscode/`。
- 暂存 `Main.java` 与 `.gitignore`，提交：`chore: 初始化项目`。
- 学习提交信息规范：`feat:`、`fix:`、`refactor:`、`docs:`、`chore:`。

**3. 基础语法与菜单开发（线下 1-2）**
- 按需补：变量、分支、循环、方法、数组、String、Scanner。
- 引入 `var` 与文本块，对比 Java 8 写法。
- 编写 `while` + `switch` 菜单，拆成 `showMenu()`、`handleChoice(int)`、`main()`。
- 提交：`feat: 添加控制台菜单框架`。

**4. 商品功能开发（线下 2）**
- 发布商品：输入名称、价格、描述，存入数组/`ArrayList`。
- 查看列表：遍历输出。
- 搜索：按名称模糊搜索，忽略大小写。
- 每个功能独立方法，完成即提交。
- 提交示例：`feat: 添加商品发布功能`、`feat: 添加商品列表展示`、`feat: 添加按名称模糊搜索`。

**5. 代码走查与验收（线下 3）**
- 检查：`main` ≤ 20 行，命名规范，无严重重复，边界不崩溃。
- Git 审查：至少 4 次规范提交，无多余文件。
- 演示：发布 3 个商品、查看、搜索、非法输入不崩溃。
- 建立 `AI_LOG.md`，记录问过的概念（如 `Scanner` 的 `nextLine()` 与 `next()` 区别）。

**6. 线上任务**
- 任务卡 1：菜单框架 + Git 提交（线下 1 后 2 天）。
- 任务卡 2：商品发布 + 列表展示（线下 2 后 2 天）。
- 任务卡 3：搜索 + AI_LOG（线下 3 前 1 天）。
- 每日文字站会：做了什么、卡在哪、下一步。
- 3 分钟录屏讲解代码结构。

## 八、思考题

1. 为什么要用接口和多态？在 Spring 的 IoC/DI 中如何体现？
2. Maven 的作用是什么？如果不用 Maven，项目依赖管理会怎样？
3. JDBC 和 MyBatis 的区别是什么？MyBatis 如何简化数据库开发？
4. 什么是 IoC 和 DI？不用 Spring 时如何管理对象依赖？各有什么优缺点？
5. AI 在编程中能帮什么、不能帮什么？如何写 Prompt 才能让 AI 输出更可靠？如何避免被 AI 的“幻觉”误导？
6. 从 V0 到 V6，每一版解决了上一版的什么痛点？如果直接写 V6，会缺失哪些关键理解？
