# 基础优先总体学习安排

> 讨论稿 v0.2｜2026-10-12。依据教师的新补充：学生目前主要会基础语法，尚不能独立整合类、集合和输入。16 周为推荐讨论方案，不是已确认的新周期。

## 1. 对新情况的判断

前一版把学生当作“已掌握 Java 8 核心，可以直接做独立 V0”，这个前提不成立。现在需要补的不是把旧语法换成新语法，而是从“认识语法”走到“能组织一个小程序”。

教师列出的 Java 基础、OOP、集合泛型、异常、Maven、JDBC/SQL、HTTP/JSON、反射注解，按待学习/待验证内容处理。即使校内课已经讲过，也需用一次独立练习确认，不能只问“听过没有”。

建议的目标表述：

> 巩固 Java 基础，独立完成含类、集合和输入处理的小程序；随后建立数据库与 Web 基础，最终能理解、修改并验证一个 Spring Boot 分层 API。

## 2. 不是所有基础都要学到同一深度

| 类别 | 内容 | 目标深度 |
|---|---|---|
| 学生必须会用 | 分支循环、方法、String、类/构造器/封装、集合泛型、常见异常 | 能在没有完整参考答案时完成小任务，并用输入验证 |
| 引入框架前要形成基本认识 | 接口、职责拆分、手工传入对象、Maven、SQL/JDBC、HTTP/JSON | 能追踪数据/调用链路，知道工具分别解决什么问题 |
| 教师演示、学生能解释即可起步 | 反射、运行时注解、自动配置、虚拟线程 | 不作为完整手写框架要求，不挡 Spring Boot 入门 |
| 本轮不设硬要求 | 完整代理框架、复杂泛型、Stream 技巧、完整继承体系、全部 Java 21 新特性 | 有余力再选做，不与基本业务能力争夺时间 |

这些是本课程的能力目标，不是声称 SQL、JDBC 或手写框架是所有 Spring Boot 入门课程的绝对先决条件。

## 3. 推荐节奏：16 周

每人每周暂按 5.5–6 小时总投入：两次 75 分钟指导，150–180 分钟自主练习，30 分钟全组验收。课时未确认，因此各周为上限内的最小任务，不再追加每日站会或整项目“写两遍”。

| 周次 | 学习重点 | 最小练习/项目增量 | 每人验收证据 | 范围控制 |
|---|---|---|---|---|
| 1 | 输入、字符串比较、分支、循环 | 菜单；录入名称并回显；固定示例；退出 | 独立改一个选项/提示；非法选项后仍能继续 | 不保存商品，不引入集合和价格 |
| 2 | 方法、参数/返回值、String、数组/遍历 | 只保存商品名称；按名称列表与搜索 | 独立拆出一个方法；解释数组与有效元素数量 | 只有名称数组，不用多组平行数组模拟商品对象 |
| 3 | 类、对象、构造器、字段、封装 | Product；创建和显示完整商品 | 独立创建两件不同商品；解释实例数据 | 不引入 Record、继承层级或数据库；价格 helper 可由教师提供 |
| 4 | ArrayList、泛型、增查改基础 | 用 ArrayList<Product> 完成发布/列表/搜索 | 独立写出主路径，并排除空名称/非法价格 | 达到“类+集合+输入”关卡，再决定是否合并团队代码 |
| 5 | 业务职责、接口、手工对象装配 | 将业务放入 ProductService，逐步引出存储接口与内存实现 | 解释入口/业务/存储各做什么；自己传入依赖对象 | 接口只围绕未来替换存储；不为每个类都配接口 |
| 6 | 异常边界、Maven、自动化测试起步 | Maven 工程；输入/业务错误处理；两项 Service 测试 | 不靠 AI 修一个错误；运行并解释一项测试 | 教师提供构建配置；本周允许补第 4–5 周缺口，不加新语法清单 |
| 7 | SQL、表/主键、参数与约束认识 | 本地数据库；商品表；增查改；成交记录表由教师提供 | 独立写一个查询和一个修改；解释条件限制 | 教师验证安装与脚本，删复杂多表查询 |
| 8 | JDBC、资源关闭、参数绑定 | JdbcProductRepository；发布/查询在重启后保留 | 追踪 Java 调用到 SQL；验证用户输入未被拼入 SQL | 先做最小增查改；不同时迁移 Web 入口 |
| 9 | 事务、存储替换与回归 | 标记已售 + 写成交记录；失败时回滚 | 解释事务的两步；验证失败不留半成功结果 | 第一次事务不做压力测试；允许人工故障点 |
| 10 | HTTP 方法/状态、JSON、请求响应 | 教师 HTTP 骨架接既有 Service；GET 查询、POST 发布 | 发送并解释一个请求；查看响应/错误 | 不让学生从零写服务器；API 工具仅此时引入 |
| 11 | API 整合；反射/注解的有限认识 | 稳定原生 API 用例；教师展示两个注解路由方法 | 说明注解、读取与调用的关系；复测一项 API | 不手写完整 MVC；选做注解路由小实验，不挡下一阶段 |
| 12 | Spring Boot、IoC/DI、构造器注入 | 从手工 new 迁到受管理对象；先迁发布/列表 | 画出两种对象装配方式；解释自己依赖谁 | 框架模板由教师预验证；保留业务规则不同时大改 |
| 13 | Spring MVC、DTO、校验、统一异常 | 搜索/详情/编辑/下架；非法请求有一致响应 | 新增一个校验并验证成功/失败 | Record 可在 DTO 处对比；分页、AOP 可选 |
| 14 | MyBatis、Spring 事务 | 替换 JDBC 访问实现，复用成交与回归场景 | 对照 Mapper/SQL/Service；验证重复成交与回滚 | 不加复杂映射；先读懂教师给的最小配置 |
| 15 | 测试、Profile、打包、说明 | 至少一项 API 集成测试；别人按 README 运行 | 独立执行构建/测试/运行；补一个回归用例 | 不引入前端框架或公网部署 |
| 16 | 缺口修复、个人现场修改、答辩 | 最终本地 API 与版本对照 | 无 AI 完成一个小规则修改并解释影响 | 不再增加技术，优先证明个人能力 |

### 周次是计划，关卡才是推进依据

- 允许不同学生以不同提示强度完成同一最小任务；不让较强者替较弱者写完。
- 某一周未通过，下一次指导先补失败点；可以删选做、减少接口数量或放宽展示要求。
- 如果基础阶段明显超过 6 周，先调整后续范围/周期，不保持所有任务不变让学生加班。

## 4. 基础学习必须嵌在小任务中

每次指导建议：

1. 教师展示一个需求/失败现象，5–10 分钟。
2. 只讲完成它所需的 1–2 个知识点，15–20 分钟。
3. 教师与学生共同完成最小示例，10–15 分钟。
4. 学生脱离完整示例独立做变式，20–25 分钟。
5. 运行边界场景、口述和反馈，余下时间。

例：讲 ArrayList 时，任务是“发布第四件商品而不需要扩容代码”，不是先讲完所有集合源码。讲接口时，任务是“以后从内存换成数据库，哪些业务调用不该跟着改”，不是先背接口定义。

## 5. 三个个人关卡

### A：基础整合关卡（第 4 周末，必要时第 6 周复核）

每人能在空白方法或有限启动骨架下：

- 创建一个 Product 对象，加入 ArrayList。
- 根据输入完成发布/列表/名称搜索的一条完整路径。
- 处理空名称或非法价格，不保存半条数据。
- 独立增加一条规则并说明验证方式。

不能只看团队作品。没过关者继续补方法/对象/集合；不让 AI 生成答案来假装通过。

### B：工程与数据/Web 理解关卡（第 11 周末）

- Maven 工程能运行；学生能解释自己写的一项测试。
- 能说明 Service、Repository 和 SQL 的调用关系。
- 数据重启后保留；能解释并演示一次事务回滚。
- 能发送 HTTP 请求，辨认请求参数、JSON 和错误响应。

反射只要求能跟着一个小例子说明流程，不要求独立做框架。

### C：Spring Boot 结业关卡（第 16 周）

- 请求到 Controller → Service → Mapper/Repository → 数据库的路径可说明。
- 学生能解释依赖从哪里来，不只会抄注解。
- 每人独立修改一条业务规则并补验证。
- 项目有运行说明和真实测试结果；身份用虚构昵称，不涉及真实支付/鉴权。

## 6. Java 21 怎么穿插，不抢基础课时间

- 第 1–2 周：使用熟悉的 Java 8 风格语法；JDK 21 是运行环境，不是一批同时要学的新语法。
- 第 3–6 周：方法、对象、集合基本任务通过后，再短对比 var、文本块、箭头 switch；可不用新语法提交。
- 第 12–13 周：在 DTO 场景比较普通类与 Record；不是用 Record 跳过 OOP 学习。
- switch 模式匹配、Record Patterns、sealed、有序集合统一 API、虚拟线程：作为短附录/教师演示，能识别价值即可。
- 不启用 Java 21 预览特性；版本归属与官方资料见特性地图。

## 7. AI 与 Git 同步降载

### AI

- 基础关卡 A 通过前：允许概念、错误和提示，不生成要提交的业务代码。
- 通过 A 后：每周选择一个小任务，先独立写，再与 AI 比较；不重写全部工程两遍。
- Web 阶段：一次辅助一个有用例的小改动，先讲预期，再检查差异和测试。
- Spring 阶段：通过个人解释检查后可有限 Agent 协作；现场能力检查不用 AI。
- 原 AI_LOG 模板中阶段的旧周次不再当作许可开关，以这些能力条件为准。

### Git

- 第一周只保存两次真实版本，允许教师指导操作；Git 不挡语法关卡。
- 第 2–4 周掌握看差异和小提交；每人的独立代码先保留。
- 第 5–6 周再教分支、合并、远程仓库和审查，不在第一周卡账号与网络。
- 通过 A 后轮换业务实现、测试审查、集成角色；每个人都写一项小改动，不固定只做文档。

## 8. 如果必须保持 12 周

这不是等量压缩版，而是降低目标的备选：

| 周次 | 重点 | 结业范围变化 |
|---|---|---|
| 1–4 | 菜单→方法/数组→普通类→集合，过基础整合关卡 | 不删个人能力检查 |
| 5–6 | Service/接口、异常、Maven、最小测试 | 用教师工程模板，削减新特性选做 |
| 7–8 | 最小 SQL/JDBC、持久化 | 只保留商品增查改，不考核独立实现成交事务 |
| 9 | HTTP/JSON；注解教师演示 | 无手写 HTTP 框架、无迷你 MVC 作业 |
| 10–11 | Boot、DI、MVC、MyBatis 基本查询/发布 | 只做发布、列表、搜索，校验与错误处理；不做完整成交、AOP、分页或前端 |
| 12 | 运行说明、复测、个人答辩 | 目标是基础分层 API 入门，不称“全面掌握 Spring” |

此路线仍以暂定每周 5.5–6 小时为前提，且需要教师验证脚手架。若实际仅 3–4 小时，应延长或继续减量；不能保证当前基础一定在 12 周内达标。

## 9. 教师准备与下一步商讨

- 第一周先发有限 Main 启动骨架、菜单需求与输入场景，不发完整答案。
- 第 3 周前准备精确金额 helper，但不要求本轮现在生成。
- 第 6/7/10/12 周前分别验证构建模板、数据库脚本、HTTP 骨架、框架工程。
- 沿用资料文档的框架版本核对要求；本次调整的是教学顺序，不是重新选一轮版本。
- 与教师确认每周课时和总周期后，再确定学生实际提交日期。

待确认：每周指导次数/时长；学生自主投入；能否采用 16 周；第一周实际诊断结果。

## 10. 教师参考（教学排序为本次建议，不是官方规定的课时）

- Java 官方学习入口按语言基础、类与对象、异常、集合等主题组织，可用于准备微练习：`https://dev.java/learn/`
- Spring Framework 官方 Constructor-based Dependency Injection 说明构造器参数如何表达对象依赖，可作为第 5 周手工装配与第 12 周框架装配的对照：`https://docs.spring.io/spring-framework/reference/core/beans/dependencies/factory-collaborators.html`
