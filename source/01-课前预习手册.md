> 第 2 课 · 线下实战 · 课前预习手册

> 本课目标：先理清需求，再尝试用 Agent 搭建仓库系统；逐步增加功能，在运行和验证中发现问题。

## 这次，我们继续做 103 仓库

上一课，我们用 Java 的输入、分支、循环、方法和 List，练习查看与搜索物品。这一课从“程序能查东西”继续往前走：谁来使用？需要哪些功能？怎样借助 Agent 做出第一版？

# 2. Agent：分清任务与执行结果
> 先认识用法，再学习操作

本课把对话式 Agent、通用型 Agent、编码型 Agent 作为便于理解的使用场景。这些能力可以重叠，不是三种互斥的技术类别。

| 使用场景 | 仓库项目里的例子 | 你要检查什么 |
| --- | --- | --- |
| 对话式助手 | 讨论需求；解释一段代码或报错。 | 是否结合了我们的实际情况？ |
| 通用任务 Agent | 整理访谈材料；形成需求文档和任务清单。 | 是否把猜测写成了已确认需求？ |
| 编码 Agent | 查看工程；修改代码；运行程序并排错。 | 改了哪些文件？运行结果是什么？ |

## 认识一个简化的工作过程

> 接收目标 → 读取上下文 → 选择下一步 → 调用可用工具 → 观察结果 → 调整或结束

工具可以是文件读取、代码编辑、终端命令或其他被允许的操作。不同工具和模式可执行的动作不同，以界面实际提供的能力为准。

## 课堂观察三个层次

回答：“可以增加借用功能。”
计划：“准备增加申请页面和审批逻辑。”
执行证据：实际改动、启动输出、输入与返回结果。

看到“已完成”后，继续检查：有没有运行？是否符合需求？异常情况有没有处理？未实际验证的内容，记录为“未验证”。

## 本课中的 Agent 扮演什么角色

本课先把 Agent 当作开发助手，帮助我们搭建普通仓库系统。给仓库系统加入自然语言查询，是以后可以探索的功能。

> 想一想：Agent 生成了一张漂亮页面，是否就说明借还流程已经可用？你会怎样验证？

# 3. Prompt 与上下文：把任务说清楚
> 少一点猜测，多一点可检查的信息

## 从一句简单要求开始

```text
帮我做一个仓库管理系统。
```

先观察缺少什么：谁使用、解决什么问题、已有材料、第一版范围、运行环境，以及怎样判断完成。

## 补充信息后的需求提示词

```text
背景：我们准备做一个学校仓库系统，学生刚学过 Java 基础。
使用者：借用人和仓库管理员，具体权限待讨论。
候选功能：物品管理、登录、借还审批、库存调整、统计报表。
任务：先问我最多 5 个关键问题，再整理简版需求卡。
要求：区分已知事实、你的假设和待确认项；给出第一版范围建议与验收标准。这一轮先不生成代码。
```

## 提示词里放什么

| 要素 | 可以提供的内容 |
| --- | --- |
| 目标 | 本轮只要完成哪一件事？ |
| 上下文 | 项目背景、已确认规则、现有代码、环境与错误原文。 |
| 约束 | 沿用什么结构？本轮修改哪些内容？哪些暂不做？ |
| 输出与验收 | 需要需求表、方案还是代码？用哪些操作检查结果？ |

## 上下文要跟着任务更新

第一轮讨论需求；下一轮带上已确认的需求与工程状态；出错时补充输入、预期、实际结果和错误信息。新开对话时重新提供关键背景，不默认工具记得所有决定。

> 练习：给“加一个借用功能”补充用户、业务规则和一条验收条件。模板文件里的方括号需要替换成真实情况。

# 4. 模拟甲乙方：把想法变成需求
> 先问清楚，再评估和开发

```text
甲方：我想知道仓库有什么东西、谁借走了、什么时候归还，还希望能查看统计。
```

甲方提出场景、规则和优先级；乙方追问、复述理解、评估实现方式；双方一起确认范围和验收。课堂轮换角色，每个人都要提出一个问题。

## 乙方可以从这些问题开始

谁可以查询、借用、审批和调整库存？
审批通过就算借出，还是实际领取后才算？
什么时候减少可用数量？归还由谁确认？
库存不足、重复提交、取消申请时怎么办？
第一版最重要的一个流程是什么？

## 项目过程与本课产出

| 环节 | 你们要留下什么 |
| --- | --- |
| 需求分析 | 用户、场景、业务规则与验收条件。 |
| 范围评估 | 本次必做项、以后再做项。 |
| 可行性与工作量评估 | 已会的、需要学习的、依赖与不确定性。 |
| 方案设计 | 页面、Java 逻辑和数据库的职责草图。 |
| 任务拆分 | 小任务、负责人、前置条件与粗略估时。 |
| 开发与验证 | 实际改动、正常与异常测试记录。 |
| 验收与交付 | 演示、启动方法、已完成与已知问题。 |

> 不要把 Agent 的假设直接当作甲方要求。把未确定的问题写下来，课堂确认后再进入开发。以上是教学用简化过程，可以随反馈调整。

# 5. 仓库功能：从整体范围到小步实现
> 先讨论全貌，再选择第一轮任务

| 候选模块 | 需要澄清的问题 |
| --- | --- |
| 物品基础管理 | 有哪些字段？如何分类、查询和维护？ |
| 登录与角色权限 | 谁能做什么？不同角色怎样区分？ |
| 借还审批 | 申请、审批、领取、归还各是什么状态？ |
| 库存调整 | 何时增减？谁可调整？是否记录原因和操作者？ |
| 统计报表 | 统计库存、借用还是逾期？时间范围和口径是什么？ |

## 下面是讨论用数据，不是已经确定的表结构

| 编号 | 物品 | 位置 | 可用数量 |
| --- | --- | --- | --- |
| A001 | 键盘 | A-01 | 5 |
| A002 | 螺丝刀 | B-02 | 12 |
| A003 | 安全帽 | C-01 | 8 |

例如：“库存数量”是总量、在库数量还是可借数量？借出 2 件以后页面显示什么？先说清定义，再决定需要保存哪些数据。

## 第一轮可以怎样缩小

一个起点示例：启动系统 → 查看物品列表 → 输入关键词 → 显示结果。课堂先由甲乙方确认本轮范围，再决定是否采用这个起点。

随后可以逐步增加登录与权限、借还流程、库存调整和统计报表。每一轮都记录：新增了什么、验证了什么、还有什么问题。

## 什么叫“完成”

把“搜索好用”改写成可检查的行为。例如：数据中存在“键盘”，输入“键”后应显示它；输入空白时如何提示、找不到时如何反馈，也需要约定。

> 今天不以功能数量评判结果。把一项需求说清、实现并验证，或者准确定位阻塞，都应留下可检查的过程记录。

# 6. 遇到问题时，把知识接起来
> 本页用于认识联系，不要求课前配置整套环境

| 遇到的问题 | 将用到的知识 |
| --- | --- |
| 物品需要名称、位置、数量 | Java 类、对象与集合。 |
| 借用规则或状态处理不正确 | 方法、条件判断与业务规则。 |
| 希望在浏览器里使用系统 | JavaWeb、HTTP 请求与响应、接口。 |
| 页面需要读取查询结果 | JSON 数据格式与前后端交互。 |
| 数据希望在程序重启后保留 | MySQL、表结构与 Java 数据访问。 |
| Agent 改完后运行失败 | 错误日志、代码改动检查与逐步排查。 |

## 先认识这条数据路线

> 浏览器提交查询 → Java 接收并处理 → 读取数据 → Java 返回结果 → 页面展示
> 读取的数据可以先来自示例列表，之后再接入 MySQL。

## 课前环境检查

□ 找到上一课项目，尝试运行、搜索与退出。
□ 能指出读取输入、方法调用和列表遍历的位置。
□ 能打开一个自己已有的 AI/Agent 工具；若不能，记录原因。
□ 把当前代码和报错带来，先保留可复现的状态。

继续使用上一课已经配置好的 Java 环境。本次课前不要求自行安装 MySQL、搭建 Spring Boot 工程、购买工具或申请 API Key；暂未配置 Agent 的同学可课堂结对操作。

## 带来三样东西

1. 工作单第 1 页：一个真实场景、三个待确认问题、一项优先功能。
2. 自己的旧程序与运行状态：能运行或具体卡点。
3. 一个想在课堂上弄明白的问题。

> 工作单第 2–4 页用于课堂，不需要提前填写。你可以直接编辑 Word，也可以在纸上写下第 1 页的答案。
